# FilePilot Lite 前端视觉规范

> 本文件只谈 UI 视觉层。功能与架构改造见 [`FEATURE_REVAMP_PLAN.md`](./FEATURE_REVAMP_PLAN.md)。
> 风格定为「**B 端骨架 + Apple 皮肤**」，2026-10-01 落地。

---

## 一、四条混搭规则

1. **骨架不动** —— 左侧导航 + 顶栏 + 卡片 + 表格的 B 端信息结构原样保留，信息密度不降。
2. **皮肤换成 Apple** —— 字体栈、大圆角、留白、系统色、弹性动效。
3. **对比度提到 Apple 水平** —— 正文 `#1D1D1F`，次要 `#6E6E73`，不用极浅灰。
4. **毛玻璃只留两个层** —— 常驻 chrome（侧栏 + 顶栏）与浮层（drawer / popper / loading mask）。
   **绝不用在卡片、表格、表单上**。原因：`backdrop-filter` 的性能开销、背景内容不可控导致文字对比度随时跌破 4.5:1、与大留白冲突。

## 二、令牌体系

**唯一事实源：`frontend/src/styles/global.css`。**
视图与组件只允许引用令牌，**不允许出现字面量颜色**。

### 中性 / 表面

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--ink` `--ink-2` `--ink-3` `--ink-4` | `#1D1D1F` `#6E6E73` `#86868B` `#A1A1A6` | `#F5F5F7` `#A1A1A6` `#8E8E93` `#636366` | 正文 → 注释四级 |
| `--bg` | `#FBFBFD` | `#1C1C1E` | 页面底 |
| `--surface` / `--surface-2` | `#FFFFFF` / `#F5F5F7` | `#2C2C2E` / `#363638` | 卡片 / 卡片悬停 |
| `--inset` | `rgba(120,120,128,.09)` | `rgba(120,120,128,.24)` | 输入框、进度条轨道 |
| `--hairline` / `--hairline-strong` | `rgba(0,0,0,.07)` / `.13` | `rgba(255,255,255,.10)` / `.18` | 发丝线 |

### 语义色（每个都配 `-soft` 浅底 + `-ink` 深字）

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--primary` | `#0071E3` | `#0A84FF` |
| `--success` | `#34C759` | `#30D158` |
| `--warning` | `#FF9500` | `#FF9F0A` |
| `--danger` | `#FF3B30` | `#FF453A` |
| `--violet` / `--info` | `#AF52DE` / `#5AC8FA` | `#BF5AF2` / `#64D2FF` |
| `--gold` | `#B87926` | `#D9A044` |

> **规则**：语义色作「背景」时用 `--x-soft`，作「文字」时必须用 `--x-ink`。
> 直接把饱和色当文字放在浅底上，对比度不达标。

### 尺度

```
圆角   --radius-sm 10 / --radius-ctl 12 / --radius 20 / --radius-lg 26 / --radius-pill 999
投影   --sh-1 卡片静置 / --sh-2 卡片悬停与浮层 / --sh-3 模态 / --sh-focus 焦点环
动效   --ease cubic-bezier(.32,.72,0,1)   --dur-fast .18s / --dur .32s / --dur-slow .5s
字号   --fs-display 34 / --fs-h1 29 / --fs-h2 20 / --fs-title 15 / --fs-body 13.5 / --fs-note 12 / --fs-micro 11
```

### 环境层（毛玻璃背景）

毛玻璃要「看得出来」，背后必须有可模糊的东西。三层缺一不可：

| 层 | 实现 | 作用 |
|---|---|---|
| 点阵纹理 | `radial-gradient(circle, var(--grid-dot) 1px, transparent 1.2px)`，`background-size: 26px 26px` | 给 blur 提供**高频参照**。没有它，模糊一个纯色 = 等于没开 |
| 环境色斑 | 4 处大半径 `radial-gradient`，色值 `--amb-a` ~ `--amb-d` | 让画布带**色相**，白卡与 chrome 才有参照物 |
| 纱罩 | `body::before` 铺一层 `var(--bg)`，`opacity: var(--ambience-veil)` | 统一控制浓度，改一个数调三档 |

**强度三档** —— 改 `<html data-ambience="...">`：

| 档位 | 浅色纱罩 | 深色纱罩 | 观感 |
|---|---|---|---|
| `quiet` | 0.62 | 0.60 | 克制，接近原来的干净白底 |
| `standard`（默认） | 0.28 | 0.24 | 明显但不抢内容 |
| `bold` | 0 | 0 | 最浓，色斑完全显现 |

**层级关系**：`body` 背景（色斑 + 点阵）→ `body::before`（纱罩，`z-index: 0`）→ `#app`（`position: relative; z-index: 1`）。
`#app` 必须建栈，否则纱罩会盖住整个应用。`el-drawer` / `el-popper` 因 `append-to-body` 且 z-index 2000+，仍在其上。

**为什么卡片仍然不上毛玻璃**：即使背景已经足够花，卡片依然保持实色。半透明卡片会让正文对比度随背后色斑漂移，在查重、日志这类长列表页尤其难读。玻璃感由「chrome 层 + 彩色画布」的对比产生，不靠卡片。

## 三、深色模式第一原则

**深色下阴影几乎不可见，层级必须改由「表面明度差」承担。**

所以所有悬停态一律写成「**表面提亮 + 极轻位移**」，而不是「投影上浮」：

```css
.card:hover {
  background: var(--surface-2);   /* 深色下从 #2C2C2E 提到 #363638 */
  transform: translateY(-2px);
}
```

另需两件事，漏了会露馅：
- `color-scheme: dark`（否则原生滚动条、表单控件仍是浅色）
- Element Plus 官方深色变量 `element-plus/theme-chalk/dark/css-vars.css` + `<html class="dark">`

## 四、主题机制

`frontend/src/composables/useTheme.js` —— 三态 `auto / light / dark`，localStorage 持久化（key `filepilot-theme`），`auto` 跟随 `prefers-color-scheme`。

- 首屏防闪白：`index.html` 内联脚本在样式与模块脚本之前就把 `data-theme` 打进 `<html>`。
- Vue 侧只改 `data-theme`；`html.dark` 由同一模块同步维护，供 Element Plus 使用。

**点击语义：切「相反」，不做三态循环。**

| 当前 | 点击后 |
|---|---|
| `auto`（系统浅色） | → `dark` |
| `auto`（系统深色） | → `light` |
| `light` | → `dark` |
| `dark` | → `light` |

**为什么不做循环**：三态循环 `auto → light → dark` 里，
当模式是 `auto` 而系统恰好是浅色时，**`auto → light` 这一步屏幕上毫无变化**，
用户会以为点击没反应，必须点两下才能变暗。改成「切成相反」之后**一次点击必定生效**。

代价：无法再手动切回 `auto`（`auto` 只作为初始默认值）。
如果需要恢复，清掉 localStorage 的 `filepilot-theme` 即可，或以后加独立入口。

## 五、新增页面的写法

1. 页面根结构用 `<PageHeader>` + `.content-stack` / `.section-stack` 包一层。
2. 卡片一律 `background: var(--surface)` + `1px solid var(--hairline)` + `--sh-1`，**不要加 backdrop-filter**。
3. 指标用 `<StatCard>`，表格用 `<DataTable>`，目标选择用 `<TargetPicker>` —— 不要各页自己写。
4. 颜色只写 `var(--*)`。写完自检：`grep -nE '#[0-9a-fA-F]{3,6}|rgba?\(' src/views/xxx.vue` 应为空（蓝底白字与 treemap 色块除外）。
5. 动效统一用 `var(--ease)`，过渡时长用 `--dur-*`。

## 八、控件级优化（第二轮）

用 `ui-design-languages` 技能做的审计，路由结论：**shadcn/ui 定骨架 + beUI 给手感 + transitions.dev 管微过渡**。

### 审计发现与修复

| # | 问题 | 修复 |
|---|---|---|
| 1 | `.meta-pill` 在 11 个视图用了 **26 次**，全站无任何样式定义 → 渲染成裸文本 | 补全局 `.meta-pill`：26px 药丸 + 前置状态圆点 |
| 2 | 动效令牌只有 1 条曲线 + 3 档时长 | 按 transitions.dev 补全 7 档时长 / 7 条缓动 / 距离·缩放·模糊档；旧 `--dur-*` 改为指向新 token 的别名 |
| 3 | 快捷入口无图标、无箭头、无点击暗示，与只读指标卡视觉同级 | 新增 `ActionTile.vue`：图标色块 + 标题 + 说明 + 箭头（hover 右移张开） |
| 4 | `el-empty` 默认线稿插画与皮肤不搭（全站 9 处） | 新增 `EmptyState.vue`；`DataTable` 增加 `#empty` 插槽，表格空态也走自绘组件 |
| 5 | 磁盘条把**金色**（Agent/AI 品牌色）当 warning 用，语义污染；与文案「90% 标红」矛盾 | 三级色改为 `--primary / --warning / --danger`；文案补齐 75% 档；进度条加 90% 阈值刻度 |

| 7 | 数值直接跳变 | `num-pop` 关键帧（位移 + 模糊 + 透明度同时收），靠 `:key` 重挂载重放 |
| 8 | `transition: all` / `transition: background` 简写 | 全部展开为具体属性 |
| 9 | 按钮按压 `scale(.97)` 无过冲 | 改用 `--ease-spring`（`cubic-bezier(.34,1.56,.64,1)`）+ `scale(.96)` |
| 10 | 主题切换只有图标替换 | 加 icon swap（旋转 + 模糊交叉）；整页改用 **View Transition API** 从按钮位置扩散的圆形揭示 |
| 11 | 页面过渡只有位移淡入 | 加模糊交叉溶解（本体系签名手法） |

### 新增组件

- **`ActionTile.vue`** —— 可点卡片：明确的 affordance + spring 按压 + 箭头张开
- **`EmptyState.vue`** —— 自绘空态（icon + 标题 + 说明 + 可选操作），结构与 shadcn 的 Empty 对齐

### 动效令牌（transitions.dev 体系）

```
时长  --duration-stagger 40 / -micro 80 / -quick 150 / -fast 250
      -medium 350 / -slow 400 / -very-slow 500      铁律：进慢出快
缓动  --ease Apple 通用 / --ease-out 出场 / --ease-spring 按压回弹
      --ease-morph 尺寸 morph / --ease-slide 指示器滑动 / --ease-bounce 徽章 / --ease-linear
距离  --dist-micro 4 / -small 6 / -base 8 / -medium 12 / -large 30
缩放  --scale-modal .96 / -dropdown .97 / -tooltip .98
模糊  --blur-fx-micro 2 / -base 3 / -strong 8
```

### 两条新增铁律

1. **禁用 `transition: all`**，逐属性枚举——通配简写会带动无关样式。
2. **禁止字面量时长**，一律走 `--duration-*`。交付前自查应为空：
   ```bash
   grep -rnoE 'transition:[^;]*[0-9]+(\.[0-9]+)?(s|ms)' src/
   ```

## 九、侧栏改造（第三轮）

### 为什么原来「笨重」

不是配色问题，是结构问题：

- 每个导航项**塞了两行**（标题 + 副标题），单项实际高度 ≈ **52px**
- 11 项 × 52px = 572px，加 4 个分组标题、品牌区、底部状态卡，全栏 ≈ **890px**
  → 普通 1080p 窗口一屏放不下，`任务中心 / 回收站 / 操作日志` 被挤到视野外
- 选中态是 240×52 的**整块高饱和实心蓝**，视觉重量盖过页面主体
- 分组标题 11px 浅灰，与相邻项只靠留白分隔，缺节奏

### 六条改动

| # | 改动 | 说明 |
|---|---|---|
| 1 | 品牌区收紧 | 徽标 36 → 32px，文案行距收 2px |
| 2 | 分组标题**吸顶** | `position: sticky; top: 0` + 玻璃底，短窗口滚动时保持可见 |
| 3 | **一项一行，52 → 34px** | 最关键的一刀，11 项省下约 200px |
| 4 | 选中态减重 | 实心蓝 → `--primary-soft` 底 + `--primary` 图标 + `--primary-ink` 文字 |
| 5 | 副标题改 **hover 展开** | `grid-template-rows: 0fr → 1fr` morph，350ms `--ease-morph` |
| 6 | 状态卡贴底 | `margin-top: 12px`，中间留弹性空隙 |

改后全栏 ≈ **645px**，一屏放得下。

### 实现要点（容易踩的两处）

1. **折叠动画的 padding 必须放在内层 wrapper**（`.nav-link__hint-inner`），放在 `0fr` 的 grid track 层会关不严。
2. **图标盒高度要对齐标题行高**（17×20px），否则 `align-items` 会让图标在展开时跟着往下飘。
   折叠态改用 `align-content: center` 居中，不受展开影响。

### 选中态备选

| 方案 | 色值 | 适用 |
|---|---|---|
| 浅 tint + 主色字 | `--primary-soft` / `--primary-ink` | **当前采用** |
| 中性灰 tint | `--surface-2` / `--ink` | 最中性，接近 macOS Finder |
| 实心主色 | `--primary` / `#fff` | 已弃用，太重 |

### ⚠️ v2 修正：单行版被否掉了

第一版把导航项压成了 **34px 单行**（副标题 hover 才展开）。实测观感是「太小太空」——
字号压到 13px、行宽右边空出约 35%，整块反而显得小气。**已回退**。

最终形态：

| 项 | 第一版（已否） | **v2（当前）** |
|---|---|---|
| 行高 | 34px 单行 | **46px 两行** |
| 标题 | 13px | **13.5px / 1.35** |
| 副标题 | hover 展开 | **常驻 11.5px** |
| 图标 | 17px | **18px**，盒高对齐标题行 |
| 选中态 | 浅 tint | 浅 tint（保留） |
| 分组标题 | 吸顶 | 吸顶（保留） |

全栏 ≈ **785px**（原 890px）。**净收益来自「选中态减重 + 分组节奏」，不是来自压高度。**

**教训**：压缩行高能省空间，但侧栏是「扫视型」而非「阅读型」组件，
横向留白一旦超过三分之一就会读作"空"，而不是"简洁"。
以后遇到同类诉求，优先减「视觉重量」（底色、边框、饱和色），不要先减「信息量」。

### v3：侧栏改为贴边通高

原先侧栏是**浮在页面里的一张圆角卡片**（外面一圈 16px 边距 + 26px 圆角 + 投影）。
改成贴边通高的 chrome 面板：

| 项 | 改前 | 改后 |
|---|---|---|
| 外边距 | 四周 16px | **0**，紧贴窗口左/上/下沿 |
| 圆角 | 26px | **0** |
| 投影 | `--sh-2` | **无**，改用 `border-right: 1px solid var(--hairline)` 分界 |
| 高度 | `calc(100vh - 32px)` 且 `top: 16px` | **`100vh`**，`top: 0` |
| 毛玻璃 | 有 | **保留**（它仍是 chrome 层） |
| 顶栏 | 居中的圆角药丸，`top: 16px` | **通栏粘性条**，`top: 0`，底发丝线 |

同时把「外观 / 收起」从顶栏与品牌区**下移到侧栏底部**，与运行状态合成一组列表项
（对应参考图里「深色模式 / 收起」那一块）：

```
[●] 本地服务正常
[☾] 外观              跟随系统
[«] 收起
```

这样做的两个附带收益：
1. **消掉一处信息重复**——顶栏原来也有「后端已连接」，和侧栏的「本地服务正常」是同一件事。
   现在桌面端只由侧栏底部承担（移动端保留顶栏里的状态 chip）。
2. **顶栏变干净**，只剩面包屑 + 日期 + 状态，主题切换在桌面端不再占位。

> 移动端（<960px）没有常驻侧栏，所以顶栏保留了一个仅移动端可见的外观切换按钮。

### v4：桌面端去掉顶栏

顶栏里四样东西，**三样在别处已有**：

| 顶栏内容 | 已有替代 |
|---|---|
| FilePilot Lite | 侧栏品牌区 |
| 扫描分析（页面名） | 页面 H1 大标题 |
| 后端已连接 · 18:29 | 侧栏底部状态（侧栏是 sticky，永远可见） |
| 10月1日 周四 | **没有替代** |

而且侧栏 `position: sticky; height: 100vh`，底部状态圆点**始终可见**，
所以顶栏在「随时知道后端活着」上也没有加分 —— 它是个纯冗余的套壳。

**做法**：`<header v-if="isMobile" class="workspace-topbar">`。
- 桌面端：不渲染顶栏，内容区直接以 `PageHeader` 的 H1 开场（`padding-top: 22px`）
- 移动端：保留这条 bar，因为它承载**汉堡按钮**（打开导航抽屉）和外观切换
- 日期随顶栏一起下线（本地工具用不上）

**如果以后想加回来**：桌面端需要一条常驻条时，优先放「唯一的新信息」，
不要再放品牌名、页面名、连接状态这三样已经在别处的东西。

### v5：让整页真正有玻璃感

**诊断**：整页一片白。卡片 `#FFFFFF` 压在 `#FBFBFD` 背景上，只差 2% 明度；
环境色斑虽然有，但还不足以让半透明的层次显出来。

**关键判断（这轮最重要的一条）**：

> 背景是**柔和的径向渐变**，对它做 `backdrop-filter` 几乎看不出任何变化 ——
> 模糊一个平滑渐变 = 平滑渐变本身。
> 真正产生「磨砂玻璃感」的是 **半透明白 + 上沿高光**，不是 blur。

所以卡片依然不上 blur：零性能成本、对比度完全可控。

| 令牌 | 改前 | 改后 |
|---|---|---|
| `--surface` | `#FFFFFF` | `rgba(255,255,255,.72)` |
| `--surface-2` | `#F5F5F7` | `rgba(120,120,128,.08)` |

### v11：对齐参考图 —— 灰底 + 纯白卡

用户给了一张目标截图（卡扣AI 仪表盘），要求「做成这种效果，但不要上面那个横框」。

**诊断**：我们的页面底 `#FBFBFD` 和卡片 `rgba(255,255,255,.72)` 几乎同色（差 2% 明度），
所以整页糊成一片。参考图的核心特征恰恰是——**卡片比页面底白**。

**这一步把 v5~v7 的「半透明玻璃卡 + 背景上色」全部回退**，改为最朴素的明度分层：

| 令牌 | v7 | **v11** |
|---|---|---|
| `--bg` | `#FBFBFD`（近白） | **`#F4F5F7`（中性浅灰，零色相）** |
| `--surface` | `rgba(255,255,255,.72)` | **`#FFFFFF`（纯白）** |
| `--surface-2` | `rgba(120,120,128,.08)` | **`#F6F7F9`** |
| `--glass` / `--glass-strong` | 半透明 | **不透明**（`#FFFFFF` / `#2C2C2E`） |
| `--blur` / `--blur-strong` | blur(26px) / blur(34px) | **`none`** |
| `--sheen` / `--sheen-card` | 玻璃高光 | **空阴影**（`0 0 0 0 rgba(0,0,0,0)`） |
| `--amb-*` / `--aur-*`（浅色） | `.02~.05` | **全部 0 —— 背景完全不带色** |
| `--sh-1` / `--sh-2` | 带 inset 高光 | **紧凑双层影**（`rgba(16,24,40,…)`） |

**深色的处理**：同样改为不透明面板（`--surface: #2C2C2E`、`--glass: #2C2C2E`），

因为它们被拼进 `box-shadow` 列表（`--sh-1: …, var(--sheen-card)`），
写成 `none` 会让**整条 box-shadow 失效**。

**参考图里还没做的两件事**（属于功能而非样式）：

1. **筛选行**（时间范围 / 刷新 / 粒度）—— 首页没有可筛选的维度；
   已有的筛选在 `操作日志`、`任务中心`、`扫描分析` 三页上。
2. **图表**（环形图 + 折线图 + 图例 chips）—— 需要引入图表库和新数据接口，
   目前只有 `磁盘容量` 的进度条与 `接口调用 TOP 5` 的排行条。

### v20-a：任务进度跨选项卡保持（修「切选项卡像被取消」）

**现象**：在一个选项卡起任务，切到另一个选项卡，回来后进度没了（看起来像任务被取消）。

**不是取消**：后端 SSE 断开只退订（`stream.finally` / `unsubscribe` 都不碰任务），前端也没有失焦或卸载取消的监听。
`cancel_requested=True` 只可能来自「点中断任务」的显式调用——日志里那几笔都是真实点击。

**真正的病**：`useJob` 的状态绑在页面组件上，切选项卡即卸载 → 订阅断、进度卡清空，而任务其实还在后端跑。

**修法**：
1. `useJob(key)` 引入身份 key，模块级 `ACTIVE_JOBS` 记住「哪个页面/哪个步骤在跑哪个任务」；
   `onMounted(restore)` 回页时自动接回进度。各页 key：scan / space / backup / junk.scan / junk.clean /
   duplicates.scan / duplicates.clean / migrate.plan / migrate.execute / projects / virtual.preview /
   virtual.plan / virtual.exec / agent。
2. `SpaceMap` 的 `watchResult()`（300ms setInterval）**卸载时没清**，改成 `watch(() => job.value?.status)`。
3. 「中断任务」加二次确认（危险动作）。
4. 中断来源进审计日志：`cancelJob` 自动附带调用栈 → 任务 `cancel_reason` → 日志 note（只写一条）。

**回归**：`tests/job_disconnect_test.py`（对照组 + 断开组，都应跑完不被取消）。

### v21-b：修一段被吞掉的 CSS（全站）+ 去掉卡片内的整宽灰带（2026-10-05）

**起因**：用户指出「除了首页，其他选项卡的背景白色都要像首页那样白」。
截图是 Virtual 页，卡片内部有**两条整宽灰带**（提示条 1058×36、"暂无任务" 1058×64），
而首页卡片内部只有 8px 细条的浅底，没有这种大灰块。

**挖出的根因有三层，按严重程度排**：

**1. `global.css` 有一处 CSS 语法错误 —— 影响全站（本次最值钱的发现）。**

原 1403 行凭空多了一个 `@media (max-width: 640px) {`，它一直吞到文件末尾（1488 行）才被闭合。
后果：**1409~1480 的全部规则只在视口 ≤640px 时生效，桌面端完全失效**，包括
`.job-detail-section`、`.job-detail-section__title`、`.job-params`（任务详情区的排版与网格）。

同段里那份 `.panel-note` 与 626 行**一字不差地重复了 40 行**，一并删除。
顺带清掉那段冗余的 `.panel-card, .form-page { max-width: 1120px }`
（`.form-page` 的 `max-width: 1120px` 早在 605 行就定义过）。

**修法**：删掉误插的 `@media` 与冗余限宽；把 `@media (max-width: 640px)` 还给真正需要在窄屏生效的
`.form-surface` / `.panel-title-row`。

> **教训：改完 CSS 要数括号。** `{` 数量 ≠ `}` 数量，就一定有块被吞。
> 这种错误不报错、不警告，只会让一大片规则静默失效 —— 而失效区域往往正好是你以为改好了的地方。
> 一条命令：`grep -o '{' global.css | wc -l` 对比 `grep -o '}' global.css | wc -l`。

**2. `.panel-note` 被 Element Plus 的样式压掉。**

EP 的 `.el-alert--info.is-light`（特异性 0,2,0）自带灰底 + `width:100%`，
压过 `.panel-note`（0,1,0），把设计意图里的「朴素一行提示」渲染成了**整宽灰带**。
作者只在旁边写了 warning 态的高优先级覆盖，**info 态漏了**。

**修法**：新增 `.panel-note.el-alert.is-light`（0,3,0）提权还原。
⚠️ **必须排在 warning 规则之前** —— 两者同为 (0,3,0)，靠后的赢，否则彩色警告会被抹平成无色。

**3. `JobProgress` 的空态用灰底。**

`.job-progress--empty` 原为 `--surface-2` 灰底 + 虚线框，在纯白卡上就是一条 1058×64 的灰带。
改成 `--surface` 白底，**虚线框保留**（空态仍可辨识）。

**刻意没做的**：不碰控件类灰底 —— `.el-segmented`（分段控件）、`.drive-chip`（盘符胶囊）、
`.exclude-toggle`、「先生成一次预览」的 `empty-state__icon`。这些灰色表达
「可点击 / 是可容纳图标的容器」，与首页 `action-tile__icon` 属同一类**小尺寸**装饰，
不是用户反感的「大片灰」。要改的话说一声。

**验证**（Playwright 实渲染，1400×1000 @2x）：

| 页面 | 探针结果 |
|---|---|
| Virtual | `.panel-note` → `rgba(0,0,0,0)` + width 342px + padding 0；`.job-progress--empty` → `rgb(255,255,255)` |
| Migrate | warning 态仍是 `rgb(255,243,224)` 橙底 + `rgb(166,92,0)` 橙字 —— 提权规则**没有**抹平彩色警告 |
| Jobs | `.job-params` → `display:grid` 恢复（原桌面端无样式） |
| 首页 | `.app-card` 仍纯白、`.section-stack` 无宽度限制 → **无回归** |

> 全站其它用 `.panel-note` 的页面（Scan / Junk / Duplicates / Backup / Projects）
> 的提示条也一并从灰带变成朴素一行 —— 这正是用户要的「都像首页一样白」。

### v22：统计卡全站统一为 StatCard（2026-10-05）

**起因**：用户对比两张截图 —— 日志页的 4 张统计卡（记录数 / 成功率 / 当前筛选 / 操作类型）

## v25-c：消息操作行「点不到」（2026-10-06）

用户反馈：**「下面选不了，一选会消失」** —— 悬停消息出现的「来自记忆 / 复制 / 重新生成」
够不到，光标一往下走就整行消失。

### 复现（Playwright，先量后改）

`.message-actions` 是 `position: absolute; top: 100%; margin-top: 4px`，
显示与否由**父级 `.message` 的 `mouseleave`** 控制（`hoverIndex`）。实测两个根因：

| 根因 | 实测数据 |
|---|---|
| **4px 悬停死区** | 消息底边 176、操作行顶边 180 → `gapMsgToRow = 4`。这 4px 里 `elementFromPoint` 返回 **`chat-scroll`**（既不在消息里也不在行里）→ 光标跨过时父级 `mouseleave` 触发 → `hoverIndex = -1` → 行当着面消失 |
| **操作行被下一条消息盖住** | 行 `top 180 / bottom 199`，下一条消息 `top 188` → **`overlapRowIntoNext = 12`**。行中心 `elementFromPoint` 返回 **`message__mark`**（下一条的 Atlas 方章）。相邻两条助手消息只隔 12px，而此行需要约 23px，伸出去的部分被后出现的兄弟节点压在上面 —— 就算够到也点不着 |

第二条才是「一选就消失」的主因：光标落到按钮位置时命中的是下一条消息，
触发的是**下一条**的 `mouseenter`，于是本条的行被收起。

### 改法（`views/Agent.vue`）

1. `margin-top: 4px` → **`padding-top: 4px`**。行的盒子从消息底边**紧贴**开始，死区归零，留白感不变。
2. 加 `.message:hover, .message:focus-within { z-index: 3 }` —— 悬停时把整条消息抬到邻条之上，
   伸出去的操作行才不会被下一条盖住。
3. 行加 `background: var(--surface)`：与主区同色，与下一条重叠时不透出脏底。

### 验证

| 检查 | 改前 | 改后 |
|---|---|---|
| `gapMsgToRow` | 4px | **0**（`margin-top: 0px` / `padding-top: 4px`） |
| 光标落在「复制」上时，可见的是哪条的行 | 下一条的 | **本条的**（`visibleBelongsToFirst: true`） |
| 按钮中心的 `elementFromPoint` | `message__mark` | **`BUTTON`「复制」** |
| 可见行数量 | — | 1 |

截图：`agent_msg_actions_check.png`

### 残留取舍（已知、未处理）

行会往下伸约 23px，而**相邻两条助手消息**只隔 12px —— 悬停时行的白底会盖住下一条消息的
顶部约 11px（截图里能看到下一条的 Atlas 方章被压住一角）。因为：

- 只有「连续两条助手消息」才会撞上，实际对话里少见；
- 只在悬停那一刻出现，移开即恢复；
- 修它要把同轮间距从 12 拉到 24（会破坏已经定下来的疏密节奏）或改成行内占位（会重新让每条变高）。

**用户没报这个，先不动；真撞上了再谈。**

### 顺带发现（未处理）

操作行靠 `opacity` + `pointer-events` 控制显隐，**键盘 Tab 仍能聚焦到看不见的按钮**
（`pointer-events: none` 不影响 tab 顺序）。这是本行改成"悬浮不占位"时就有的老问题，
不属本次修复范围。

## v25-d：「部分选项卡切换还是白屏一下」（2026-10-06）

用户第二次反馈切页闪白，且指明是**部分**选项卡。**不是 v23 那个过渡问题复发**。

### 定位（先量后改）

逐路由装 rAF 帧采样器，记录切换后 800ms 内每帧：遮罩是否存在 / 遮罩底色 / 内容区子元素
最大 opacity。结果干净利落：

| 路由 | 遮罩在场时段 | 遮罩底色 |
|---|---|---|
| `/jobs` | **21~429ms** | `rgba(251,251,253,0.72)` |
| `/trash` | 24~427ms | 同上 |
| `/logs` | 111~437ms | 同上 |
| `/`（首页） | 36~443ms | 同上 |
| 其余 8 个路由 | **0 帧** | — |

「部分」正好等于用了 `v-loading` 的那 4 个页面（Home / Jobs / Logs / Trash）。
全程 `minMaxOp = 1`、空白帧 0 —— **v23 的过渡修复没有失效**，它管的是「页面半透明漏底色」，
管不到这层遮罩，两者是不同问题。

抓 95ms 那一帧看到实况：**新页的白色遮罩盖上来，把「还没填上内容的空白区」和
「已经渲染出来但被罩住的卡片」一起洗成一片白**，旧页还在半透明淡出 —— 观感就是白屏闪一下。

### 顺带查出一条死规则

```css
.el-loading-mask { background-color: var(--glass); }   /* 浅色下 --glass = 纯白不透明 */
```

这行**从来没生效过**：Element Plus 的 `v-loading` 会把 `--el-mask-color` 的值
**写成内联样式**，内联压过样式表。所以实际显示的一直是那层近白。

### 改法（`styles/global.css`，一行）

```css
.el-loading-mask { background-color: var(--inset) !important; }
```

- 必须 `!important`，否则盖不住内联样式。
- 用 `--inset`（一成灰）而不是白：**方向从「提亮」改成「压暗」**，不再泛白，
  同时保留遮罩该有的两件事——挡住误点、留住中间的转圈。
- **刻意不动 `--el-mask-color`**：它同时管着 `.el-overlay`（弹窗遮罩），
  改它会波及所有弹窗。只针对 `.el-loading-mask`。

### 验证

复测同一套帧采样：4 个路由的遮罩底色由 `rgba(251,251,253,0.72)` 变为
`rgba(120,120,128,0.1)`；90ms 那一帧的卡片恢复清晰可读、不再被洗白。
`minMaxOp` 仍为 1、空白帧仍为 0。截图 `tab_load_mask_check.png`。

### 试过但证明无效的

**改深页面底色（`--bg`）**。我一度以为「一大片 #f4f5f7 看着就是白」才是根因，
渲染了 `#eceef1` / `#e7e9ed` 两档对比 —— **同一帧几乎看不出区别**，因为那一帧主要被遮罩罩着，
页面底色根本露不出来。这条路作废，没写进代码。

（顺带记一个坑：`documentElement.style.setProperty('--bg', …)` 与
`body.style.setProperty('--bg', …)` **都改不动实际背景** —— 变量读数变了，但
`getComputedStyle(body).backgroundColor` 纹丝不动。做底色预览只能用
`page.addStyleTag` 直接覆盖 `html, body, body::before`。）

### 改法（只动 `views/Agent.vue` 一个函数）

1. 新增 `BOOT_KEY = 'filepilot.agent.booted'` 存进 `sessionStorage` —— 它跟着 WebView / 标签页的生命周期走，
   应用一关就没了，正好用来区分「新一次启动」与「同一次运行内切走再切回」。
2. `initConversations()` 分两条路：
   - **本次启动首访** → 直接 `newConversation()` + `hydrating.value = false`，不读也不恢复 localStorage 里那条；
   - **同一次运行内再进来** → 沿用当前会话，切走再切回不打断。
3. 旧会话一条没删，仍在左栏任务列表 / 历史对话里可翻。

### 顺手修掉的老 fallback 坑（实测翻车）

原逻辑第二段：

```js
const known = stored && conversations.value.some(c => c.conversation_id === stored)
const id = known ? stored : conversations.value[0]?.conversation_id || stored || newConversationId()
```

**新建的空会话在发出第一条消息之前不会落库**，`list_conversations` 自然拿不到它 → `known` 为 false →
退回 `conversations[0]`（最近一条历史会话）。后果：用户切去「重复文件」再切回来，
画面上会**冒出一条毫不相干的旧对话**，刚建好的欢迎页被顶掉。

改为**只认 localStorage 里那条**：

```js
const id = stored || conversations.value[0]?.conversation_id || newConversationId()
```

代价：若那条会话在后端已被删除，恢复出来就是空的（显示欢迎页）—— 比「莫名跳到别人的会话」可接受得多。

## v27：操作日志页「切进来先白屏一下」（2026-10-07）

### 现象

切到「操作日志」选项卡时先白一下。

### 诊断手法（四件套，可复用）

1. **CDP screencast 逐帧录屏**（`Page.startScreencast`）—— 抓到真实画面帧：侧栏完好、右侧内容区一片空白。
   `page.screenshot()` 单张截图**会错过这个窗口**（自身耗时 50~100ms），逐帧取证必须用 screencast。
2. **页面内 rAF 逐帧读 `.workspace-content` 子元素 opacity** —— `maxOp` **恒为 1**。
   结论：过渡 CSS 没问题，**不是**「露底色」。
3. **PerformanceObserver 抓 longtask** —— 累计 **1251ms**，单次最长 **646ms**。
4. **对照实验**（回收站 vs 操作日志）—— 回收站 longtask **0 个 / 0ms**，完全正常。

> 关键坑：长任务期间 rAF 回调**根本不执行**，所以光看 rAF 数据看不出空白帧；
> 必须配合 screencast 截图或 longtask 才能定位。

### 根因

Logs 页把 **464 条日志一次性全渲染进 el-table**（464 行 × 5 列，其中 time / type / path / result
四列都挂了自定义 slot），主线程阻塞 1.25 秒。

与此同时，**离场页的 `opacity` 淡出跑在合成器线程上，不受主线程阻塞影响、继续推进到 0**；
而新页面的图层还没被提交绘制 —— 屏幕上就只剩空白底色。这就是「白屏一下」。

**注意**：`.el-loading-mask` 的底色早已是 `rgba(120,120,128,0.1)`（v25-d 修过），
**不是这次白屏的来源**，别再往那儿改。

### 改法（`views/Logs.vue`）

1. **分页**：`page` / `pageSize = 50` / `paged` computed，`DataTable` 改绑 `paged`。
   筛选条件或搜索词变化时回到第 1 页（`watch`），页码用 `Math.min` 对越界做兜底。
2. **灌数据前先让出一帧**：

```js
function nextPaint() {
  return new Promise(resolve => requestAnimationFrame(() => requestAnimationFrame(resolve)))
}

const data = await getLogs()
await nextPaint()          // 先把「骨架 + 遮罩」交给浏览器画出来
raw.value = data.logs || []
```

## v28：任务卡「百分比和秒数不是实时显示的」（2026-10-09）

### 现象

用户截图：任务卡上「已运行 45 秒」「35% · 45秒」两个数字**都不动**，
而当时的阶段是「正在统计条目数（用于进度）」。

### 先量：把它们各自的来源拆开

| 数字 | 来源 | 为什么不动 |
|---|---|---|
| **秒数** | `JobProgress.vue` 的 `elapsed` computed | computed 只在依赖变化时重算，而它读的"现在时刻"是**非响应式**的 `new Date()` → **后端两次事件之间有多久，秒数就冻多久** |
| **百分比（普通任务）** | `JobContext.progress` 的 `percent` | 预热统计阶段 `total=None` → 后端**必然**给 0%，且整段一动不动 |
| **百分比（Agent 任务）** | `agent_task._publish` | `total=None` 时 `fraction` **写死 0.5** → 整段恒等于 `(index+0.5)/total`（截图里的 35% 就是 (2+0.5)/7） |

抓真实 SSE 时间线复现（把 `count_entries` 拖慢到 15 秒）：

```
  t(s)  percent  message
  0.02        0  正在统计条目数（用于进度）
  ...       (15 秒内 300 条事件，percent 全是 0，消息一字不变)
 15.29      100  已完成
```

**事件在推、但每条都不带新信息** —— 界面看起来就是卡死的。

### 改法

1. **秒数挂一个自己会走的时钟**（`components/JobProgress.vue`）：
   加 `nowTick` ref + 1 秒 `setInterval`（只在 running 且未 finished 时开），
   `elapsed` 依赖 `nowTick` 而不是 `new Date()`。**从此不依赖后端有没有推事件。**
2. **计数阶段把实时条目数写进消息**（`fsutil.iter_entries` 的 `_counting`）：
   `"正在统计条目数 —— 已数 12,345 项"`。这一刻唯一真实且在动的信号就是它。
3. **没有总数就不摆死数字**：新增 `.bar.is-unknown` 不确定态 ——
   一个来回扫动的片段 + 右侧只留实时秒数（不再显示一个恒为 0% 的百分比）。
   有总数时照旧走真实百分比。
4. **运行中的条子加一道流动高光**（`--bar-sheen`，明 38% / 暗 26%）：
   百分比在"没有总数"的区间本来就算不出来，高光把「还在动」画出来 ——
   **宽度仍然是真实百分比，不编数字**。

### 验证

组件级探针（`frontend/_probe_jobprogress.html`，系统 Edge 真实渲染，已删）：

| 用例 | 期望 | 实测 |
|---|---|---|
| 预热统计（total 缺失） | 不确定态、无百分比 | `bar is-unknown` + `jp-slide` 在跑 + 只显示「46 秒」 |
| Agent 任务（percent 35） | 实心条 + 高光 | 宽度 240px + `jp-sheen` |
| 有总数 | 真实百分比 + 计数 | `620 / 1000 · 62% · 46 秒` |
| 秒数在走 | 两次读数不同 | **46 秒 → 49 秒**（不依赖任何后端事件） |
| `--bar-sheen` token | 明暗两套都读得到 | 38% / 26% |

不确定态轨迹连续采样 14 帧：可见 **12/14** 帧，左边缘平滑递增（597→683→-168→82→5→91…→691）。

集成验证（临时后端 + 真实 Job + 真实 SSE，探针页自己 POST 建任务再轮询）：

```
秒数取值:    1 → 2 → 3 → … → 16          （16 个不同值，逐秒在走）
百分比取值:  0 → 4 → 10 → 12 → 18 → 23 → 25 → 6 → 17 → 29 → 40 → 52 → 58 → 69
不确定态帧:  19/32（预热统计那一段）
消息:        已数 200 → 10,200 → 20,000 → … → 89,600 项
```

### 刻意没做什么

- **没给"没有总数"的阶段编一个平滑上涨的假百分比。** 项目一贯的规矩是不假装精确
  （同 `_bounded_walk` 超限如实标 `truncated`）。要真的百分比就得先数一遍，
  而"数"这个过程本身没有分母 —— 所以那一段用不确定态，动的信息交给实时条目数。
- **没动 `_emit` 的 0.2 秒节流。** 它在高频进度下是对的（实测计数阶段稳定 ~5 事件/秒）。
- **没改 Agent 任务的 `fraction=0.5`。** 步内确实无法量化，保持不动是诚实的；
  现在有高光 + 实时秒数 + 实时条目数三条"活着的"信号。

### 已知遗留（未改，等确认）

**百分比会跨阶段倒退**：预热统计结束后，分母从"条目数"换成"候选文件数"，
于是百分比从 25% 掉回 6%（实测序列里的 `… → 23 → 25 → 6 → 17 …`）。
合理做法是按 `phase_index` 给每个阶段划一段百分比区间（像 `agent_task` 对步骤做的那样），
但那要改 `JobContext.progress` 的语义，属于设计变更 —— **先不动**。

## v29：Agent 任务卡「跨对话泄漏」（2026-10-09）

### 现象

在对话 A 里启动了一个任务，切到对话 B 之后**还能看见 A 的任务卡**，看起来像是 B 启动的。

### 根因（一行）

`views/Agent.vue` 里 `const job = useJob('agent')` —— **key 写死成常量**。
`useJob` 内部是模块级的 `ACTIVE_JOBS` Map，按这个 key 存"当前订阅的任务"，
写死常量就等于**整个页面共用一个任务槽**；而 `switchConversation()` 只换 id / 存 localStorage / 重载记忆，
**完全没碰 `job`** → 卡片原样留在屏幕上。

顺带第二个后果：`startPlanTree()` 的 `if (jobRunning.value)` 拦的是**本槽位**的任务，
提示也只说「有任务正在运行」，不告诉你是谁在跑。

### 改法

1. **`useJob(key)` 支持传函数**：`useJob(() => conversationId.value)`，
   槽位名每次现算（`keyOf()`），`attach` / `restore` / `cancel` 三处调用点都改用它。
2. **`restore()` 在槽位为空时清掉手上的任务**（新增 `clear()`，只断连接、**绝不取消后端任务**）。
   这是关键：不清的话切走以后卡片还在。`onMounted(restore)` 的行为对其他页面不变（null → 清空是空操作）。
3. **`Agent.vue` 在会话定下来之后认领任务卡**：`switchConversation()` / `newConversation()` /
   `initConversations()` 各调一次 `job.restore()`（**必须在改完 `conversationId` 之后**）。
4. **"一次只跑一个 Agent 任务"改成查后端的全局限制**（`listJobs(50)` 找 `agent_task` 的非终态任务），
   而不是看本会话的 `jobRunning` —— 否则换个会话就能再起一个，限制等于没有。
   查后端还带来两个好处：能查到**不是本页启动**的任务（比如刷新过页面），
   并能拿到 `params.conversation_id` 把警告说清楚是谁在跑。

### 验证（打包版 + 真实 UI，Playwright 六项）

| # | 断言 | 结果 |
|---|---|---|
| ① | A 里启动任务后出现任务卡 | ✓ |
| ② | 新建对话 B 后任务卡消失 | ✓ |
| ③ | 切回 A 后任务卡回来（任务一直在跑，中断按钮也在） | ✓ |
| ④ | 空对话 C 里没有任务卡 | ✓ |
| ⑤ | 在 C 里点「开始分析」不会起第二个任务 | ✓ |
| ⑥ | 警告指名了另一个对话 | ✓ 「帮我找出 C://Users//fa…」里有个任务正在运行… |

### 刻意没做什么

- **没把「开始分析」按钮做成全局禁用。** 它按"本会话"判断（`:disabled="!!jobRunning"`），
  跨会话的情况**点了才提示、并指名是谁**。禁用按钮 + 不解释，比点一下给一句清楚的话更难懂。
- **没动空会话不落库的行为。** 测试里"新建的 B 切走后再也找不到"是**既有设计**
  （空会话在发第一条消息前不落库，见 v26），不是这次引入的。
- **没给任务加"属主会话"字段。** 后端 `Job` 依然不带 `conversation_id`，
  归属是从 `job.params.conversation_id` 读的（Agent 任务本来就带）——
  够用，不用改 schema。

### 顺带发现（不是这次改出来的）

`tests/smoke_test.py` 的「保护目录护栏」3 项**只能对着"工作目录 = 仓库"的后端跑**：
它把样本建在仓库根（`_smoke_protected`）来验证"项目自身不可写"，
而**打包版**的"项目自身"是 `release\Atlas` —— 对打包版跑必然失败。
已写进测试文件的 docstring。

- hover：边框加深 + `--inset` 底 + `--chart-shadow` + 上移 1px（阴影/位移属"可视化例外"）。

## v34：空间地图的「页边距」与「三列对齐」（2026-10-10）

用户截图：「你不觉得这个界面没有页边距吗，还有这么看着一点也不对称一点也不协和」。

### 病因一：漏了一个 class，整块零内边距（硬 bug）

```
<section class="app-card viz">          ✗ 没有内边距
<section class="app-card panel-card viz"> ✓ 24px
```

`padding: 24px` 定义在 **`.panel-card`** 上，`.app-card` 本身**没有内边距**。
结果卡片里的面包屑、指标、卡片网格、页脚**全部贴着卡片边框** —— 看起来就是"没有页边距"。
这是**看代码看不出来的那一类**（class 少了不会报错、不影响功能），只能靠截图或量几何发现。

### 病因二：指标的三列和卡片的三列不在同一条竖线上

指标块原本在 `.viz-head__text`（`flex:1`）里、右边被 3D 数据城占掉 200px，
于是指标每列 305px、卡片每列 379px —— **两组竖线错开**，这就是"不协和"。

**改法**：把指标块**移出头部**，成为头部之后的独立一行，占满整宽。
头部只留「面包屑 + 口径说明 + 3D 数据城」（3D 城同时缩到 168px）。
于是指标和卡片共用同一个三列网格。

### 验证（量几何，不看截图）

```

左内边距 25px · 右内边距 25px · 卡片宽 1208
指标三列左边缘: 285 / 674 / 1064   宽 379 / 379 / 379
卡片三列左边缘: 285 / 674 / 1064   宽 379 / 379 / 379   ← 完全一致
3D 数据城 1275-1443（与卡片网格右缘 1443 对齐，差 0px）
```

截图 `docs/images/space_viz_v34_light.png` / `docs/images/space_viz_v34_dark.png`。

### 可复用的教训

**"看起来没有页边距"先查 class 漏没漏**：本项目 `.app-card` 只负责边框/圆角/阴影，
**内边距一律由 `.panel-card` 提供**。新写卡片时少写一个 class 就会变成贴边。

## v35：跨页接力 —— 把 13 个孤岛串起来（2026-10-11）

### 问题

调研同类项目时核实的断层：**`useConfig` 只共享盘符和排除规则，不共享当前目录；
各页的 `path` 都是自己的 `ref`；没有任何页面读 `route.query`**。

后果是一个很蠢的场景：

> 在空间地图看到 `$WinREAgent 1.6 GB` → 想去清理它 → 得自己切到「垃圾清理」，
> **再把同一个目录选一遍**。同一件事用户做两遍。

### 做法（最小接力，不新增功能）

- 新增 `composables/useHandoff.js`：
  - `useHandoff()` → `handoffTo(name, path, origin)`，把目录塞进路由 query（`?focus=<目录>&from=<来源>`）
  - `useHandoffTarget(targetRef)` → 目标页 `onMounted` 时取走并**填进输入框**，返回 `handed` / `from`
- 新增 `components/HandoffNote.vue`：一条「已带入目录 X · 从空间地图带过来」+「知道了」
- 空间地图底部加一行「**对这个目录：查重 · 清理 · 迁移 · 项目雷达**」——
  作用在**当前层目录**（不是某一张卡），放在 footer 里，不破坏「整卡可点下钻」
- 目标页：`Duplicates` / `Junk` / `Projects`（填 `path`）、`Migrate`（填 `source`）

### ★ 刻意不自动开跑

接力只把目录**填好**，按钮仍然要用户点 —— 项目一贯的规矩是「先出清单、等用户确认」，
自动开跑会绕过那一步。

### 验证（打包版 + 真实点击，Playwright）

```
空间地图底部: 对这个目录： ["查重","清理","迁移","项目雷达"]
点「查重」    → #/duplicates?focus=…&from=space   提示条 ✓ 目录已填 ✓
点「清理」    → #/junk?focus=…&from=space         提示条 ✓ 目录已填 ✓
点「迁移」    → #/migrate?focus=…&from=space      提示条 ✓ 目录已填 ✓
点「项目雷达」 → #/projects?focus=…&from=space     提示条 ✓ 目录已填 ✓
errs: []
```

截图 `docs/images/handoff_space_light.png` / `handoff_target_check.png`。

### 新增页面的约定

**凡是接受「目录输入」的选项卡，都应该接一次 `useHandoffTarget(它的 path ref)` 并在模板里放
`<HandoffNote>`** —— 否则那个页面就成了新的孤岛。

## v36：结果 → 执行的统一契约（2026-10-11）

用户问：「我进行文件整理查询等任务之后，给我的结果我怎么执行呢？」

查下来发现：**整理预览其实能执行**（四步：预览 → 选目标 → 出计划 → 确认执行），
但**入口全藏在页面下方**；而项目雷达扫完**根本没有出口**。

### 现状（改之前）

| 页面 | 结果之后 | 顺不顺 |
|---|---|---|
| 垃圾清理 / 重复文件 | 勾选 → 底部浮出「送进隔离区」 | 顺 |
| 跨盘迁移 | 「生成迁移计划」→「确认执行迁移」，**并且写了"这一步不动文件"** | 最顺 |
| **整理预览** | 四步藏在 3 个滚动区里；计划按钮**灰着不说为什么** | **卡在这** |
| **项目雷达** | **没有任何出口** | 死胡同 |
| 扫描分析 / 空间地图 | 靠接力求生口 | 顺 |
| Agent 助手 | 计划卡「继续执行」/「只执行安全项」 | 顺 |

### 契约（三条）

> **凡是产出「清单」的页面，都走同一个骨架：看（只读）→ 挑（勾选/调整）→ 执行（先进隔离区，可回滚），
> 而且页面里必须写明"下一步在哪"。**

1. **能就地执行的 → 给主按钮**：垃圾清理 / 重复文件 / 整理预览 / 跨盘迁移 / Agent 助手
2. **不能就地执行的 → 给接力按钮**：用 `components/NextSteps.vue` 把当前目录带去对应页面
   （空间地图 / 扫描分析 / 项目雷达 / 整理预览 / 跨盘迁移 都已接）
3. **多步流程必须带步骤指示**，且**按钮禁用时要说明原因**（不许干灰着）

### 本轮落地的改动

- **整理预览**：顶部加三步指示（预览 · 出计划 · 确认执行，当前步高亮、走过的打勾）；
  计划按钮上方补「这一步只生成计划，不会动任何文件。确认清单之后再执行。」
  （**照抄迁移页那句** —— 同一件事，迁移页说清了，这一页没说）；
  提示语从"清单包含 N 个文件"改成**会说原因**：没选目标根目录时直接写
  「先选一个「整理到」的目标根目录 —— 选好后这里会列出要移动的文件数」。
- **项目雷达**：结果区补「迁到别的盘 / 清理构建产物 / 空间地图」。
- **整理预览 + 跨盘迁移**：也补上接力出口（它们同样是清单型页面，不该是路的尽头）。

### 为什么值得定成契约

13 个页面里原本「结果之后怎么办」有 **4 种不同答法**（勾选式 / 计划式 / 接力式 / 没有），
用户每换一页都要重新找一遍。真正的问题不是"某个页面缺个按钮"，
而是**没有一个共同骨架** —— 补按钮只能治一个页面，定契约才能防止再长出第二个「整理预览」。
