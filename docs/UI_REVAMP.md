# FilePilot Lite 前端视觉规范

> 本文件只谈 UI 视觉层。功能与架构改造见 [`FEATURE_REVAMP_PLAN.md`](./FEATURE_REVAMP_PLAN.md)。
> 风格定为「**B 端骨架 + Apple 皮肤**」，2026-10-01 落地。

---

## 一、四条混搭规则

1. **骨架不动** —— 左侧导航 + 顶栏 + 卡片 + 表格的 B 端信息结构原样保留，信息密度不降。
2. **皮肤换成 Apple** —— 字体栈、大圆角、留白、系统色、弹性动效。
3. **对比度提到 Apple 水平** —— 正文 `#1D1D1F`，次要 `#6E6E73`，不用极浅灰。
4. **毛玻璃只留两个层** —— 常驻 chrome（侧栏 + 顶栏）与浮层（drawer / popper / loading mask）。
   **绝不用在卡片、表格、表单上**。原因：`backdrop-filter` 的性能开销、背景内容不可控导致文字对比度随时跌破 4.5:1、与大留白冲突。

## 二、令牌体系

**唯一事实源：`frontend/src/styles/global.css`。**
视图与组件只允许引用令牌，**不允许出现字面量颜色**。

### 中性 / 表面

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--ink` `--ink-2` `--ink-3` `--ink-4` | `#1D1D1F` `#6E6E73` `#86868B` `#A1A1A6` | `#F5F5F7` `#A1A1A6` `#8E8E93` `#636366` | 正文 → 注释四级 |
| `--bg` | `#FBFBFD` | `#1C1C1E` | 页面底 |
| `--surface` / `--surface-2` | `#FFFFFF` / `#F5F5F7` | `#2C2C2E` / `#363638` | 卡片 / 卡片悬停 |
| `--inset` | `rgba(120,120,128,.09)` | `rgba(120,120,128,.24)` | 输入框、进度条轨道 |
| `--hairline` / `--hairline-strong` | `rgba(0,0,0,.07)` / `.13` | `rgba(255,255,255,.10)` / `.18` | 发丝线 |

### 语义色（每个都配 `-soft` 浅底 + `-ink` 深字）

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--primary` | `#0071E3` | `#0A84FF` |
| `--success` | `#34C759` | `#30D158` |
| `--warning` | `#FF9500` | `#FF9F0A` |
| `--danger` | `#FF3B30` | `#FF453A` |
| `--violet` / `--info` | `#AF52DE` / `#5AC8FA` | `#BF5AF2` / `#64D2FF` |
| `--gold` | `#B87926` | `#D9A044` |

> **规则**：语义色作「背景」时用 `--x-soft`，作「文字」时必须用 `--x-ink`。
> 直接把饱和色当文字放在浅底上，对比度不达标。

### 尺度

```
圆角   --radius-sm 10 / --radius-ctl 12 / --radius 20 / --radius-lg 26 / --radius-pill 999
投影   --sh-1 卡片静置 / --sh-2 卡片悬停与浮层 / --sh-3 模态 / --sh-focus 焦点环
动效   --ease cubic-bezier(.32,.72,0,1)   --dur-fast .18s / --dur .32s / --dur-slow .5s
字号   --fs-display 34 / --fs-h1 29 / --fs-h2 20 / --fs-title 15 / --fs-body 13.5 / --fs-note 12 / --fs-micro 11
```

### 环境层（毛玻璃背景）

毛玻璃要「看得出来」，背后必须有可模糊的东西。三层缺一不可：

| 层 | 实现 | 作用 |
|---|---|---|
| 点阵纹理 | `radial-gradient(circle, var(--grid-dot) 1px, transparent 1.2px)`，`background-size: 26px 26px` | 给 blur 提供**高频参照**。没有它，模糊一个纯色 = 等于没开 |
| 环境色斑 | 4 处大半径 `radial-gradient`，色值 `--amb-a` ~ `--amb-d` | 让画布带**色相**，白卡与 chrome 才有参照物 |
| 纱罩 | `body::before` 铺一层 `var(--bg)`，`opacity: var(--ambience-veil)` | 统一控制浓度，改一个数调三档 |

**强度三档** —— 改 `<html data-ambience="...">`：

| 档位 | 浅色纱罩 | 深色纱罩 | 观感 |
|---|---|---|---|
| `quiet` | 0.62 | 0.60 | 克制，接近原来的干净白底 |
| `standard`（默认） | 0.28 | 0.24 | 明显但不抢内容 |
| `bold` | 0 | 0 | 最浓，色斑完全显现 |

**层级关系**：`body` 背景（色斑 + 点阵）→ `body::before`（纱罩，`z-index: 0`）→ `#app`（`position: relative; z-index: 1`）。
`#app` 必须建栈，否则纱罩会盖住整个应用。`el-drawer` / `el-popper` 因 `append-to-body` 且 z-index 2000+，仍在其上。

**为什么卡片仍然不上毛玻璃**：即使背景已经足够花，卡片依然保持实色。半透明卡片会让正文对比度随背后色斑漂移，在查重、日志这类长列表页尤其难读。玻璃感由「chrome 层 + 彩色画布」的对比产生，不靠卡片。

## 三、深色模式第一原则

**深色下阴影几乎不可见，层级必须改由「表面明度差」承担。**

所以所有悬停态一律写成「**表面提亮 + 极轻位移**」，而不是「投影上浮」：

```css
.card:hover {
  background: var(--surface-2);   /* 深色下从 #2C2C2E 提到 #363638 */
  transform: translateY(-2px);
}
```

另需两件事，漏了会露馅：
- `color-scheme: dark`（否则原生滚动条、表单控件仍是浅色）
- Element Plus 官方深色变量 `element-plus/theme-chalk/dark/css-vars.css` + `<html class="dark">`

## 四、主题机制

`frontend/src/composables/useTheme.js` —— 三态 `auto / light / dark`，localStorage 持久化（key `filepilot-theme`），`auto` 跟随 `prefers-color-scheme`。

- 首屏防闪白：`index.html` 内联脚本在样式与模块脚本之前就把 `data-theme` 打进 `<html>`。
- Vue 侧只改 `data-theme`；`html.dark` 由同一模块同步维护，供 Element Plus 使用。

**点击语义：切「相反」，不做三态循环。**

| 当前 | 点击后 |
|---|---|
| `auto`（系统浅色） | → `dark` |
| `auto`（系统深色） | → `light` |
| `light` | → `dark` |
| `dark` | → `light` |

**为什么不做循环**：三态循环 `auto → light → dark` 里，
当模式是 `auto` 而系统恰好是浅色时，**`auto → light` 这一步屏幕上毫无变化**，
用户会以为点击没反应，必须点两下才能变暗。改成「切成相反」之后**一次点击必定生效**。

代价：无法再手动切回 `auto`（`auto` 只作为初始默认值）。
如果需要恢复，清掉 localStorage 的 `filepilot-theme` 即可，或以后加独立入口。

## 五、新增页面的写法

1. 页面根结构用 `<PageHeader>` + `.content-stack` / `.section-stack` 包一层。
2. 卡片一律 `background: var(--surface)` + `1px solid var(--hairline)` + `--sh-1`，**不要加 backdrop-filter**。
3. 指标用 `<StatCard>`，表格用 `<DataTable>`，目标选择用 `<TargetPicker>` —— 不要各页自己写。
4. 颜色只写 `var(--*)`。写完自检：`grep -nE '#[0-9a-fA-F]{3,6}|rgba?\(' src/views/xxx.vue` 应为空（蓝底白字与 treemap 色块除外）。
5. 动效统一用 `var(--ease)`，过渡时长用 `--dur-*`。

## 八、控件级优化（第二轮）

用 `ui-design-languages` 技能做的审计，路由结论：**shadcn/ui 定骨架 + beUI 给手感 + transitions.dev 管微过渡**。

### 审计发现与修复

| # | 问题 | 修复 |
|---|---|---|
| 1 | `.meta-pill` 在 11 个视图用了 **26 次**，全站无任何样式定义 → 渲染成裸文本 | 补全局 `.meta-pill`：26px 药丸 + 前置状态圆点 |
| 2 | 动效令牌只有 1 条曲线 + 3 档时长 | 按 transitions.dev 补全 7 档时长 / 7 条缓动 / 距离·缩放·模糊档；旧 `--dur-*` 改为指向新 token 的别名 |
| 3 | 快捷入口无图标、无箭头、无点击暗示，与只读指标卡视觉同级 | 新增 `ActionTile.vue`：图标色块 + 标题 + 说明 + 箭头（hover 右移张开） |
| 4 | `el-empty` 默认线稿插画与皮肤不搭（全站 9 处） | 新增 `EmptyState.vue`；`DataTable` 增加 `#empty` 插槽，表格空态也走自绘组件 |
| 5 | 磁盘条把**金色**（Agent/AI 品牌色）当 warning 用，语义污染；与文案「90% 标红」矛盾 | 三级色改为 `--primary / --warning / --danger`；文案补齐 75% 档；进度条加 90% 阈值刻度 |

| 7 | 数值直接跳变 | `num-pop` 关键帧（位移 + 模糊 + 透明度同时收），靠 `:key` 重挂载重放 |
| 8 | `transition: all` / `transition: background` 简写 | 全部展开为具体属性 |
| 9 | 按钮按压 `scale(.97)` 无过冲 | 改用 `--ease-spring`（`cubic-bezier(.34,1.56,.64,1)`）+ `scale(.96)` |
| 10 | 主题切换只有图标替换 | 加 icon swap（旋转 + 模糊交叉）；整页改用 **View Transition API** 从按钮位置扩散的圆形揭示 |
| 11 | 页面过渡只有位移淡入 | 加模糊交叉溶解（本体系签名手法） |

### 新增组件

- **`ActionTile.vue`** —— 可点卡片：明确的 affordance + spring 按压 + 箭头张开
- **`EmptyState.vue`** —— 自绘空态（icon + 标题 + 说明 + 可选操作），结构与 shadcn 的 Empty 对齐

### 动效令牌（transitions.dev 体系）

```
时长  --duration-stagger 40 / -micro 80 / -quick 150 / -fast 250
      -medium 350 / -slow 400 / -very-slow 500      铁律：进慢出快
缓动  --ease Apple 通用 / --ease-out 出场 / --ease-spring 按压回弹
      --ease-morph 尺寸 morph / --ease-slide 指示器滑动 / --ease-bounce 徽章 / --ease-linear
距离  --dist-micro 4 / -small 6 / -base 8 / -medium 12 / -large 30
缩放  --scale-modal .96 / -dropdown .97 / -tooltip .98
模糊  --blur-fx-micro 2 / -base 3 / -strong 8
```

### 两条新增铁律

1. **禁用 `transition: all`**，逐属性枚举——通配简写会带动无关样式。
2. **禁止字面量时长**，一律走 `--duration-*`。交付前自查应为空：
   ```bash
   grep -rnoE 'transition:[^;]*[0-9]+(\.[0-9]+)?(s|ms)' src/
   ```

## 九、侧栏改造（第三轮）

### 为什么原来「笨重」

不是配色问题，是结构问题：

- 每个导航项**塞了两行**（标题 + 副标题），单项实际高度 ≈ **52px**
- 11 项 × 52px = 572px，加 4 个分组标题、品牌区、底部状态卡，全栏 ≈ **890px**
  → 普通 1080p 窗口一屏放不下，`任务中心 / 回收站 / 操作日志` 被挤到视野外
- 选中态是 240×52 的**整块高饱和实心蓝**，视觉重量盖过页面主体
- 分组标题 11px 浅灰，与相邻项只靠留白分隔，缺节奏

### 六条改动

| # | 改动 | 说明 |
|---|---|---|
| 1 | 品牌区收紧 | 徽标 36 → 32px，文案行距收 2px |
| 2 | 分组标题**吸顶** | `position: sticky; top: 0` + 玻璃底，短窗口滚动时保持可见 |
| 3 | **一项一行，52 → 34px** | 最关键的一刀，11 项省下约 200px |
| 4 | 选中态减重 | 实心蓝 → `--primary-soft` 底 + `--primary` 图标 + `--primary-ink` 文字 |
| 5 | 副标题改 **hover 展开** | `grid-template-rows: 0fr → 1fr` morph，350ms `--ease-morph` |
| 6 | 状态卡贴底 | `margin-top: 12px`，中间留弹性空隙 |

改后全栏 ≈ **645px**，一屏放得下。

### 实现要点（容易踩的两处）

1. **折叠动画的 padding 必须放在内层 wrapper**（`.nav-link__hint-inner`），放在 `0fr` 的 grid track 层会关不严。
2. **图标盒高度要对齐标题行高**（17×20px），否则 `align-items` 会让图标在展开时跟着往下飘。
   折叠态改用 `align-content: center` 居中，不受展开影响。

### 选中态备选

| 方案 | 色值 | 适用 |
|---|---|---|
| 浅 tint + 主色字 | `--primary-soft` / `--primary-ink` | **当前采用** |
| 中性灰 tint | `--surface-2` / `--ink` | 最中性，接近 macOS Finder |
| 实心主色 | `--primary` / `#fff` | 已弃用，太重 |

### ⚠️ v2 修正：单行版被否掉了

第一版把导航项压成了 **34px 单行**（副标题 hover 才展开）。实测观感是「太小太空」——
字号压到 13px、行宽右边空出约 35%，整块反而显得小气。**已回退**。

最终形态：

| 项 | 第一版（已否） | **v2（当前）** |
|---|---|---|
| 行高 | 34px 单行 | **46px 两行** |
| 标题 | 13px | **13.5px / 1.35** |
| 副标题 | hover 展开 | **常驻 11.5px** |
| 图标 | 17px | **18px**，盒高对齐标题行 |
| 选中态 | 浅 tint | 浅 tint（保留） |
| 分组标题 | 吸顶 | 吸顶（保留） |

全栏 ≈ **785px**（原 890px）。**净收益来自「选中态减重 + 分组节奏」，不是来自压高度。**

**教训**：压缩行高能省空间，但侧栏是「扫视型」而非「阅读型」组件，
横向留白一旦超过三分之一就会读作"空"，而不是"简洁"。
以后遇到同类诉求，优先减「视觉重量」（底色、边框、饱和色），不要先减「信息量」。

### v3：侧栏改为贴边通高

原先侧栏是**浮在页面里的一张圆角卡片**（外面一圈 16px 边距 + 26px 圆角 + 投影）。
改成贴边通高的 chrome 面板：

| 项 | 改前 | 改后 |
|---|---|---|
| 外边距 | 四周 16px | **0**，紧贴窗口左/上/下沿 |
| 圆角 | 26px | **0** |
| 投影 | `--sh-2` | **无**，改用 `border-right: 1px solid var(--hairline)` 分界 |
| 高度 | `calc(100vh - 32px)` 且 `top: 16px` | **`100vh`**，`top: 0` |
| 毛玻璃 | 有 | **保留**（它仍是 chrome 层） |
| 顶栏 | 居中的圆角药丸，`top: 16px` | **通栏粘性条**，`top: 0`，底发丝线 |

同时把「外观 / 收起」从顶栏与品牌区**下移到侧栏底部**，与运行状态合成一组列表项
（对应参考图里「深色模式 / 收起」那一块）：

```
[●] 本地服务正常
[☾] 外观              跟随系统
[«] 收起
```

这样做的两个附带收益：
1. **消掉一处信息重复**——顶栏原来也有「后端已连接」，和侧栏的「本地服务正常」是同一件事。
   现在桌面端只由侧栏底部承担（移动端保留顶栏里的状态 chip）。
2. **顶栏变干净**，只剩面包屑 + 日期 + 状态，主题切换在桌面端不再占位。

> 移动端（<960px）没有常驻侧栏，所以顶栏保留了一个仅移动端可见的外观切换按钮。

### v4：桌面端去掉顶栏

顶栏里四样东西，**三样在别处已有**：

| 顶栏内容 | 已有替代 |
|---|---|
| FilePilot Lite | 侧栏品牌区 |
| 扫描分析（页面名） | 页面 H1 大标题 |
| 后端已连接 · 18:29 | 侧栏底部状态（侧栏是 sticky，永远可见） |
| 10月1日 周四 | **没有替代** |

而且侧栏 `position: sticky; height: 100vh`，底部状态圆点**始终可见**，
所以顶栏在「随时知道后端活着」上也没有加分 —— 它是个纯冗余的套壳。

**做法**：`<header v-if="isMobile" class="workspace-topbar">`。
- 桌面端：不渲染顶栏，内容区直接以 `PageHeader` 的 H1 开场（`padding-top: 22px`）
- 移动端：保留这条 bar，因为它承载**汉堡按钮**（打开导航抽屉）和外观切换
- 日期随顶栏一起下线（本地工具用不上）

**如果以后想加回来**：桌面端需要一条常驻条时，优先放「唯一的新信息」，
不要再放品牌名、页面名、连接状态这三样已经在别处的东西。

### v5：让整页真正有玻璃感

**诊断**：整页一片白。卡片 `#FFFFFF` 压在 `#FBFBFD` 背景上，只差 2% 明度；
环境色斑虽然有，但还不足以让半透明的层次显出来。

**关键判断（这轮最重要的一条）**：

> 背景是**柔和的径向渐变**，对它做 `backdrop-filter` 几乎看不出任何变化 ——
> 模糊一个平滑渐变 = 平滑渐变本身。
> 真正产生「磨砂玻璃感」的是 **半透明白 + 上沿高光**，不是 blur。

所以卡片依然不上 blur：零性能成本、对比度完全可控。

| 令牌 | 改前 | 改后 |
|---|---|---|
| `--surface` | `#FFFFFF` | `rgba(255,255,255,.72)` |
| `--surface-2` | `#F5F5F7` | `rgba(120,120,128,.08)` |

### v11：对齐参考图 —— 灰底 + 纯白卡

用户给了一张目标截图（卡扣AI 仪表盘），要求「做成这种效果，但不要上面那个横框」。

**诊断**：我们的页面底 `#FBFBFD` 和卡片 `rgba(255,255,255,.72)` 几乎同色（差 2% 明度），
所以整页糊成一片。参考图的核心特征恰恰是——**卡片比页面底白**。

**这一步把 v5~v7 的「半透明玻璃卡 + 背景上色」全部回退**，改为最朴素的明度分层：

| 令牌 | v7 | **v11** |
|---|---|---|
| `--bg` | `#FBFBFD`（近白） | **`#F4F5F7`（中性浅灰，零色相）** |
| `--surface` | `rgba(255,255,255,.72)` | **`#FFFFFF`（纯白）** |
| `--surface-2` | `rgba(120,120,128,.08)` | **`#F6F7F9`** |
| `--glass` / `--glass-strong` | 半透明 | **不透明**（`#FFFFFF` / `#2C2C2E`） |
| `--blur` / `--blur-strong` | blur(26px) / blur(34px) | **`none`** |
| `--sheen` / `--sheen-card` | 玻璃高光 | **空阴影**（`0 0 0 0 rgba(0,0,0,0)`） |
| `--amb-*` / `--aur-*`（浅色） | `.02~.05` | **全部 0 —— 背景完全不带色** |
| `--sh-1` / `--sh-2` | 带 inset 高光 | **紧凑双层影**（`rgba(16,24,40,…)`） |

**深色的处理**：同样改为不透明面板（`--surface: #2C2C2E`、`--glass: #2C2C2E`），

因为它们被拼进 `box-shadow` 列表（`--sh-1: …, var(--sheen-card)`），
写成 `none` 会让**整条 box-shadow 失效**。

**参考图里还没做的两件事**（属于功能而非样式）：

1. **筛选行**（时间范围 / 刷新 / 粒度）—— 首页没有可筛选的维度；
   已有的筛选在 `操作日志`、`任务中心`、`扫描分析` 三页上。
2. **图表**（环形图 + 折线图 + 图例 chips）—— 需要引入图表库和新数据接口，
   目前只有 `磁盘容量` 的进度条与 `接口调用 TOP 5` 的排行条。

### v20-a：任务进度跨选项卡保持（修「切选项卡像被取消」）

**现象**：在一个选项卡起任务，切到另一个选项卡，回来后进度没了（看起来像任务被取消）。

**不是取消**：后端 SSE 断开只退订（`stream.finally` / `unsubscribe` 都不碰任务），前端也没有失焦或卸载取消的监听。
`cancel_requested=True` 只可能来自「点中断任务」的显式调用——日志里那几笔都是真实点击。

**真正的病**：`useJob` 的状态绑在页面组件上，切选项卡即卸载 → 订阅断、进度卡清空，而任务其实还在后端跑。

**修法**：
1. `useJob(key)` 引入身份 key，模块级 `ACTIVE_JOBS` 记住「哪个页面/哪个步骤在跑哪个任务」；
   `onMounted(restore)` 回页时自动接回进度。各页 key：scan / space / backup / junk.scan / junk.clean /
   duplicates.scan / duplicates.clean / migrate.plan / migrate.execute / projects / virtual.preview /
   virtual.plan / virtual.exec / agent。
2. `SpaceMap` 的 `watchResult()`（300ms setInterval）**卸载时没清**，改成 `watch(() => job.value?.status)`。
3. 「中断任务」加二次确认（危险动作）。
4. 中断来源进审计日志：`cancelJob` 自动附带调用栈 → 任务 `cancel_reason` → 日志 note（只写一条）。

**回归**：`tests/job_disconnect_test.py`（对照组 + 断开组，都应跑完不被取消）。

### v21-b：修一段被吞掉的 CSS（全站）+ 去掉卡片内的整宽灰带（2026-10-05）

**起因**：用户指出「除了首页，其他选项卡的背景白色都要像首页那样白」。
截图是 Virtual 页，卡片内部有**两条整宽灰带**（提示条 1058×36、"暂无任务" 1058×64），
而首页卡片内部只有 8px 细条的浅底，没有这种大灰块。

**挖出的根因有三层，按严重程度排**：

**1. `global.css` 有一处 CSS 语法错误 —— 影响全站（本次最值钱的发现）。**

原 1403 行凭空多了一个 `@media (max-width: 640px) {`，它一直吞到文件末尾（1488 行）才被闭合。
后果：**1409~1480 的全部规则只在视口 ≤640px 时生效，桌面端完全失效**，包括
`.job-detail-section`、`.job-detail-section__title`、`.job-params`（任务详情区的排版与网格）。

同段里那份 `.panel-note` 与 626 行**一字不差地重复了 40 行**，一并删除。
顺带清掉那段冗余的 `.panel-card, .form-page { max-width: 1120px }`
（`.form-page` 的 `max-width: 1120px` 早在 605 行就定义过）。

**修法**：删掉误插的 `@media` 与冗余限宽；把 `@media (max-width: 640px)` 还给真正需要在窄屏生效的
`.form-surface` / `.panel-title-row`。

> **教训：改完 CSS 要数括号。** `{` 数量 ≠ `}` 数量，就一定有块被吞。
> 这种错误不报错、不警告，只会让一大片规则静默失效 —— 而失效区域往往正好是你以为改好了的地方。
> 一条命令：`grep -o '{' global.css | wc -l` 对比 `grep -o '}' global.css | wc -l`。

**2. `.panel-note` 被 Element Plus 的样式压掉。**

EP 的 `.el-alert--info.is-light`（特异性 0,2,0）自带灰底 + `width:100%`，
压过 `.panel-note`（0,1,0），把设计意图里的「朴素一行提示」渲染成了**整宽灰带**。
作者只在旁边写了 warning 态的高优先级覆盖，**info 态漏了**。

**修法**：新增 `.panel-note.el-alert.is-light`（0,3,0）提权还原。
⚠️ **必须排在 warning 规则之前** —— 两者同为 (0,3,0)，靠后的赢，否则彩色警告会被抹平成无色。

**3. `JobProgress` 的空态用灰底。**

`.job-progress--empty` 原为 `--surface-2` 灰底 + 虚线框，在纯白卡上就是一条 1058×64 的灰带。
改成 `--surface` 白底，**虚线框保留**（空态仍可辨识）。

**刻意没做的**：不碰控件类灰底 —— `.el-segmented`（分段控件）、`.drive-chip`（盘符胶囊）、
`.exclude-toggle`、「先生成一次预览」的 `empty-state__icon`。这些灰色表达
「可点击 / 是可容纳图标的容器」，与首页 `action-tile__icon` 属同一类**小尺寸**装饰，
不是用户反感的「大片灰」。要改的话说一声。

**验证**（Playwright 实渲染，1400×1000 @2x）：

| 页面 | 探针结果 |
|---|---|
| Virtual | `.panel-note` → `rgba(0,0,0,0)` + width 342px + padding 0；`.job-progress--empty` → `rgb(255,255,255)` |
| Migrate | warning 态仍是 `rgb(255,243,224)` 橙底 + `rgb(166,92,0)` 橙字 —— 提权规则**没有**抹平彩色警告 |
| Jobs | `.job-params` → `display:grid` 恢复（原桌面端无样式） |
| 首页 | `.app-card` 仍纯白、`.section-stack` 无宽度限制 → **无回归** |

> 全站其它用 `.panel-note` 的页面（Scan / Junk / Duplicates / Backup / Projects）
> 的提示条也一并从灰带变成朴素一行 —— 这正是用户要的「都像首页一样白」。

### v22：统计卡全站统一为 StatCard（2026-10-05）

**起因**：用户对比两张截图 —— 日志页的 4 张统计卡（记录数 / 成功率 / 当前筛选 / 操作类型）
是「白底 + 细边框，没有图标、没有注释、数字 27px」，而首页的是「渐变蓝图标 + 42px 数字 + 底部注释」。
要求「像这种都要变成首页那种效果」。

**根因**：全站存在**两套统计卡**，只有首页用了 `StatCard` 组件，其余页面都用一套叫
`.metric-strip` 的朴素版本（`global.css:751`）。两者视觉规格完全不同：

| | `.metric-strip`（旧） | `StatCard`（首页） |
|---|---|---|
| 图标 | 无 | 32×32 渐变蓝底 + 白图标 |
| 数字 | `clamp(20px,2vw,27px)` | `clamp(30px,2.7vw,42px)` |
| 注释 | 无 | 有 |
| 圆角 / 投影 | `--radius-ctl` (12px) / 无 | `--radius` (20px) / `--sh-1` |

**改法**：8 个页面（Logs / Scan / Junk / Duplicates / Migrate / Backup / Virtual / Projects）
的 `<section class="metric-strip">` 全部换成 `<section class="stats-grid">` + `<StatCard v-for>`
（与首页同一容器、同一组件）。数据结构从 `{ label, value }` 改为 `{ title, value, note, icon, tone }`。
`.metric-strip` 的 CSS 定义随之删除（已无引用）。

> ⚠️ **坑**：第一次 `grep metric-strip` 时用了 `| head -20`，被截断，
> 只看到 5 个页面就以为改完了 —— 实际有 **8 个**（Migrate / Projects / Scan 被截掉）。
> 批量替换后的「残留检查」**不要加 head 截断**。

**注释的设计原则**：注释只放**补充信息**，不复述上面的大数字。有数字字段的就量化
（如「占全部项目的 12%」「压缩到原来的 31%」「平均每目录 8.4 个」），
没有的就写一句说明（如「移动前请确认目标盘放得下」）。
**不做**「标题的复读」（如「原始体积 → 压缩前大小」）。

**验证**（Playwright，1400×1000 @2x，遍历 9 个页面）：

- 首页 4 卡、日志页 4 卡均正常，图标为 `linear-gradient(145deg, #35a1ff, …)` + 白图标
- **9 个页面零编译错误、零运行时错误**（仅有 favicon 的 404）
- 其余 7 页 `cards=0` 属**预期** —— 它们的统计卡包在 `v-if="result"` 里，没跑过任务就不渲染
- 16 个新用到的 Element Plus 图标名已逐个核对存在（`Tickets/Menu/Filter/CircleCheck/Warning/Coin/Files/DocumentCopy/Box/FolderDelete/Grid/Lock/PieChart/Timer/FolderOpened/Clock`）

> 未验证项：其余 7 页的卡片**实际渲染效果只验证到「无报错」层面**，因为触发真实扫描/迁移
> 会污染用户的日志与磁盘。代码路径与日志页完全一致（同组件 + 同数据结构）。

## v23：选项卡切换 / 启动的闪白闪黑（2026-10-06）

用户反馈：切选项卡「有的会先白屏一下或者黑屏一下」，且每次打开 Agent 选项卡都先看到「你想让 Atlas 做什么？」空欢迎页。
验证方式：Playwright + rAF 逐帧探针（不是看截图猜）。

### 根因（三层，同一类病）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `App.vue` 的 `.page-enter-*` | 交叉淡入是「旧页 150ms 淡出 + 新页从 `opacity:0` 250ms 淡入」。新页在头 250ms 里始终不是 100% 不透明，而 `.workspace-content` 自己没有底色 → 透出来的是 `body` 的 `--bg`（浅色 `#f4f5f7` / 深色 `#1c1c1e`）。**这就是白一下/黑一下的物理来源** |
| 2 | 13 个路由级懒加载 | Vue Router 会卡住这次导航直到 chunk 下载完；页面数据又是挂载后才请求 → 没打开过的选项卡首访更慢、首帧还是空壳 |
| 3 | `main.js` 直接 `mount` | 初始路由的 chunk 还没就绪就挂载 → 先画出一帧「侧栏在、内容区空着」的半成品（实测 3 帧 ≈ 50ms） |
| 4 | `Agent.vue` hero 条件 `!messages.length` | 记忆恢复是异步的，恢复期间 `messages` 为空 → 空欢迎页先渲染，等记忆回来才被替换。**用户看到的"那个界面"就是这段空窗期** |

### 改法

| 文件 | 改动 |
|---|---|
| `App.vue` | 进场**刻意不写任何规则**（新页首帧就 100% 不透明）；离场页 `position:absolute` + `z-index:2` 压在上层淡出。任何一帧都有不透明页面垫底，结构上不可能露出底色，而「旧页淡去、新页显形」的过渡感保留 |
| `router/index.js` | 新增 `collectViewLoaders()`，导出 13 个页面的 chunk loader |
| `main.js` | ① `load` 后分批预取全部路由 chunk（间隔 160ms，避免一帧内塞 13 个模块转换）；② 改为 `router.isReady().catch().then(mount)`，首帧就是完整页面 |
| `Agent.vue` | 新增 `hydrating` 闸门（初始 true）：恢复完成前 hero 与示例胶囊都不渲染；`switchConversation` 也走同一道闸门。`initConversations()` 提到 config/status 之前并行跑 —— 它不依赖那两者，串在后面等于白等 |

### 逐帧验证数据（Playwright rAF 采样，合成模型：背景可见度 = 1 − max(子元素 opacity)）

| 项 | 改前 | 改后 |
|---|---|---|
| 16 次切换（13 浅色 + 3 深色）`minMaxOpacity` | — | **全部 = 1** |
| 露出底色的帧数 `leakFrames` | — | **0** |
| 离场页 z-index | auto | 2（确实压在进场页之上） |
| 导航提交耗时（点击 → 路由生效） | — | 21–77ms（预取生效，首访不再等 chunk） |
| 启动「半成品帧」 | 3 帧 | **0 帧**，首屏内容出现从 358ms → 246ms |
| Agent 页 hero 出现帧数 | — | **0**；135ms 就渲染出 10 条历史消息 |
| 「新建任务」空态 | — | 仍正常出现（用户主动要空白页，不受闸门影响） |

慢放取帧对照（把离场淡出临时放慢到 1.4s 才抓得到）：`tab_switch_before_check.png`（对照组：整片发白）
vs `tab_switch_after_check.png`（新页已完整铺底、旧页在上层淡出）。Agent 恢复态：`agent_restore_check.png`。

### 刻意没做的

- **不加 `<KeepAlive>`**：能让切回原地复原，但 13 个页面都靠 `onMounted` 拉数据，常驻后数据会停在离开那一刻，得给 Home/Jobs/Trash/Logs 等逐个补 `onActivated` 节流刷新 —— 收益是「更顺滑」，代价是「数据可能过期」，本轮不做（用户选了只修闪屏）。
- **不给 `.workspace-content` 加底色**：内容区本来就要透出光晕层，加不透明底会把设计推翻。从「不让新页变半透明」下手才是正解。
- **Agent 页与其它页的 `is-flush` 内边距差异**（0 vs 28/32/48）在切换瞬间仍是硬切：离场页会在 150ms 内平移 28px。因为它在同步淡出、幅度小于一个圆角，实测不可察觉，不做动画化的补间。
- **没改默认路由**：程序启动仍落首页，Agent 仍是侧栏第二项。
