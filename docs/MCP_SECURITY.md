# MCP Server 安全边界（2026-10-12）

> `backend/mcp_server.py` 的威胁模型与**如实声明**。结论都在真机跑过一遍验证（见文末「验证方式」）。
> 目的：把"它到底能看到什么、能干什么、哪里其实比你以为的宽"写清楚，
> 而不是给一句"只读所以安全"糊过去。

---

## 一、它是什么

`Atlas.exe --mcp --allow <目录>` 起一个 **stdio + JSON-RPC 2.0** 的 MCP server，
让 Claude Code / Codex / Cursor 这类客户端用上 Atlas 的扫描、查重、垃圾分析、空间地图、相似图片能力。

**没有新增运行时依赖** —— 协议手写（`mcp_server.py` 不到 500 行），不引 `mcp` 官方包。

---

## 二、安全模型：三条线

| 约束 | 做法 | 边界是否硬 |
|---|---|---|
| **看得见什么** | 默认**一个目录都看不见**，必须 `--allow <目录>` 显式放行；只放行该目录子树 | ✅ 硬（路径类工具一律先过白名单） |
| **能干什么** | **只暴露只读工具**：7 个工具里没有任何删除 / 移动 / 写入 / 回滚 | ✅ 硬（没有写工具的注册） |
| **返回多大** | 每个工具的清单都有条目上限，超了如实标 `truncated` | ✅ 硬（`_trim`／`depth` 封顶） |

### 已经验过的事实

- 空白名单时，路径类工具（scan / space_tree / duplicates / junk / similar）一律返回
  `参数有问题：没有放行任何目录…`，**不会**静默返回空结果。
- 工具数固定 **7** 个；`tools/list` 只暴露 `name / description / inputSchema`。

## 三、⚠️ 两条**不受白名单约束**的出口（必须知道）

这两个工具的 `needs_allow = False`，**空白名单也能调**。它们不读任何**用户目录**，
但仍是信息出口 / 花钱出口，所以单独列出：

| 工具 | 越界在哪 | 为什么这么做 | 风险 |
|---|---|---|---|
| `atlas_overview` | 不回白名单，返回**整机盘符容量、各盘剩余、全局 jobs / 隔离区统计** | 是"系统信息"不是"用户文件"，且看图先要盘符列表 | 低：暴露的是全机磁盘容量与工具自身任务数，不含文件名 / 路径 |
| `atlas_explain_item` | 不回白名单，且**会联网 + 消耗 token** | 解释一个待清理项要调 DeepSeek | 中：能把任意 `item` 描述发到模型；调用方需自己克制频率 |

> **给客户端使用者的建议**：把这两个工具当作"即使没放行目录也开放"的通道来对待。
> 若你的场景要求"零联网"，就别把 `atlas_explain_item` 交给自动化 Agent 随意调用。

## 四、其它如实声明

1. **协议版本原样回显**。`initialize` 时把客户端发来的 `protocolVersion` **原样回显**，
   没有做版本协商 / 校验。
   *验证*：发 `9999-99-99` 会得到同样一串。后果：客户端与 server 若语义不兼容，
   双方都不会报错，只会在调用工具时才出问题。
2. **错误信息走 `isError: true` 的 content**，不是 JSON-RPC `error`。
   白名单 / 参数问题按"工具结果"返回，让模型自己看懂并纠正；只有"没有这个工具 / 不支持的方法"
   才走 JSON-RPC `error`。**stdout 只出现协议消息**，诊断一律走 stderr（混一行就废掉整个连接）。
3. **路径判定靠 `Path.resolve()`**：Windows 上会把盘符大小写、`..`、短名收敛成规范形式，
   并**跟随符号链接 / 目录联接**。因此：
   - 白名单目录内的**联接若指向白名单之外**，`resolve()` 后落在外面 → **被拒**（联接逃逸被堵死）。
   - 判定要求目标是**已存在的目录**（`is_dir()`），不存在的路径直接拒。
4. **`depth` 封顶 1–4**、单工具清单最多 200 条、扫描大文件最多 30 条、垃圾每档 50 条 ——
   防止一次调用把磁盘或模型上下文打爆。
5. **中文描述依赖 UTF-8 强制**：Windows 默认按 GBK 编码标准流，工具描述里有中文。
   `force_utf8()` 把 stdin/stdout/stderr 强制成 UTF-8 并统一 `\n` 分帧，否则客户端收到乱码。
   打包版（`--noconsole`）下 `sys.stdout` 为 `None`，此处会把 fd 0/1/2 重新包起来。

## 五、明确的"不给"

- **不给写工具**：删除 / 移动 / 清理 / 回滚 / 隔离区还原，一个都不暴露给 MCP。
  MCP 客户端能做的上限就是"看清单"，执行永远要回到图形界面里点。
- **不给全盘默认**：默认空白名单。这是刻意的 —— 宁可第一次配起来麻烦，也不要"装上就全盘可见"。
- **不做远程 transport**：只支持 stdio（本地子进程）。没有 HTTP / WebSocket 监听口，
  不存在"被局域网里别台机器连上"的攻击面。

## 六、验证方式（可复现）

```bash
# 空白名单启动，观察 stderr
Atlas.exe --mcp     # stderr: "没有 --allow，任何目录都访问不了…"

# 放行两个目录
Atlas.exe --mcp --allow D:\Downloads --allow D:\Docs
```

单测：`tests/test_mcp_security.py`（覆盖白名单子树放行 / 白名单外拒绝 / 空白名单全拒 /
`needs_allow` 边界 / 无写类工具名）。

```bash
PYTHONPATH=. python -m pytest tests/test_mcp_security.py -q
```

---

## 七、一句话总结

> MCP server 是**"只读 + 白名单 + 只走 stdio"**的窄口子：
> 路径类工具越不出 `--allow`；但 `atlas_overview`（全机盘符容量）与
> `atlas_explain_item`（联网 + token）**是刻意放在白名单之外的**，用之前心里要有数。
