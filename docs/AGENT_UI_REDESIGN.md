## 逐项规格

### 1. 空态（无消息时）

- 输入框**垂直居中**于视口（整页高度由 `.agent-shell` 接管：桌面 `calc(100vh - 76px)`、移动端 `calc(100vh - 48px)`），发第一条消息后过渡到顶部消息流。
- 输入框下方排 4 枚示例胶囊（沿用现有 EXAMPLES）：胶囊 = `--surface` 底 + `--hairline` 描边 + `--ink-2` 文字，hover 描边与文字变 `--primary`。
- **不放任何额外说明文字**（没有「试试这几句」这种引导句，胶囊自身即含义——沿用 v8 文案准则）。

### 2. 消息流

| 元素 | 规格 |
|---|---|
| 用户消息 | **右对齐**，`--primary-soft` 气泡，圆角 18px（右下 6px），max-width 75%。**去掉「你」标签** |
| 助手消息 | **左对齐，无气泡纯文本**（`--ink`，14px / 1.7），max-width 85%。来源标签与 token 数收成消息末尾一行 11px `--ink-3` 小字：`本地规则 · 0 token` / `DeepSeek · 326 token` |
| 消息间距 | 同角色连续 12px，跨角色 20px |
| 滚动 | 消息区独立滚动，**保留可见滚动条**（长列表规则） |

### 3. 计划卡（保留结构，只换皮肤）

内联在对应助手消息下方，与助手消息左对齐同宽：

- 卡片 = `--surface` + `--hairline` + `--sh-1` + 圆角 16px（不上 backdrop-filter）；
- 头行：计划名 600 字重 + 动作 code 胶囊（`--inset` 底、`--ink-3`、等宽字体）；
- 参数区：每行 `键：值`，13px `--ink-2`，值用等宽；
- 操作行：`执行这个计划`（主色填充）+ `存成配方`（默认描边）；
- **全部旧令牌换新**：`--text-muted → --ink-3`、`--border → --hairline`、`--text-primary → --ink`、`--text-secondary → --ink-2`。

### 4. 进度卡（替代右侧「执行进度」面板）

- 任务启动后，**一张进度卡内联插入对话流末尾**，复用 `JobProgress` 组件（逻辑零改动）；
- 任务结束后进度卡收成一条助手消息式摘要：「已完成 · 释放 2.4 GB · 查看 →」（跳任务中心）；
- 卡片左侧带 2px 主色竖条，与对话气泡区分（它是「系统状态」不是「说的话」）。

### 5. 输入区（吸底）

- 与消息流同宽（760px 居中），吸底固定，上方 24px 渐隐遮罩（提示上方还有内容，与侧栏渐隐同一手法）；
- **一体式输入框**：圆角 20px、`--surface` 底 + `--hairline` 描边、聚焦时 `--sh-focus`；
- 左侧：**配方按钮**（星形图标，18px）；右侧：**发送按钮**（主色圆形，内嵌框内右下）；
- Enter 发送 / Shift+Enter 换行（替代现在的 Ctrl+Enter）；
- 输入框下方居中一行 11px `--ink-3`：`本地规则优先 · DeepSeek（deepseek-chat）已就绪` 或 `本地规则 · 未配置 API Key`。

### 6. 配方弹层

- 从输入框左侧按钮弹出（Element Plus popover，浮层规范：毛玻璃 + `--sh-2`）；
- 列表项：配方名（600）+ 一行小字（动作 · 保存时间）；点击 → 原句填入输入框（不直接发送，给用户确认机会）；
- 行尾「删除」文字按钮（danger 文字色，无底色）；
- 空态：一行 `暂无配方`（不用 EmptyState 大图标——弹层里放不下也不需要）。

### 7. 降级提示（未配置 API Key 时）

- 现有整行 `el-alert` 删除，改为输入框**上方一条内联细提示**：`--warning-soft` 底 + `--warning-ink` 字、圆角 10px、12px，一行高度；
- 文案：`未配置 DEEPSEEK_API_KEY，当前仅本地规则可用`（去劝说、去流程说明，配置方法不进 UI）。

### 8. 删除清单

| 删除 | 理由 |
|---|---|
| 右侧栏三张卡（执行进度 / 配方 / 本地动作） | 进度 → 内联进度卡；配方 → 弹层；动作清单 → 对开发者的说明，用户不需要 |
| 页头 2 个 meta 胶囊 | 模型状态已收进输入框下方小字，重复 |
| 气泡上的「你 / 本地规则 / DeepSeek」大标签 | 用户气泡靠位置与颜色自解释；助手来源收成末尾小字 |
| 对话卡面板的「对话」标题 | 整页都是对话，标题冗余 |

### 9. 不动的部分

- `agentChat` / 配方增删 / 任务启动的全部逻辑与接口；
- 计划卡的信息结构（动作 + 参数 + 双按钮）；
- `JobProgress` 组件内部；
- PageHeader 组件本身（**本页已不再使用它**，但组件保留给其他 13 个页面）。

## v19-f：向主流 Agent 对齐（2026-10-02）

用户要求「看看和市面上的 agent 界面还有什么不一样的」。对比后按落差排序，分两档落地。

### 我们的独有优势（优化时不能弄丢）

| 独有 | 说明 |
|---|---|
| **计划卡 → 一键本地执行** | 市面 agent 只给文本；我们是「说完直接变成任务」，可回滚、可在任务中心看进度 |
| 零 token / 本地规则优先 | 消息末尾显示「本地规则 · 0 token」，本地认不出才调模型 |
| 只读预检 → 确认 → 执行 | 危险动作有二次确认，这是纯聊天式 agent 没有的一层 |

> 结论：这套「对话 + 计划 + 执行」是差异化主体，**不要把它做回一个普通聊天框**。

### P1：流式输出（后端 + 前端）

| 位置 | 改动 |
|---|---|
| `backend/services/agent.py` | 新增 `STREAM_SYSTEM_PROMPT`（先一句中文说明，再 ```` ```json ```` 计划）、`_iter_deepseek_stream()`（标准库 urllib 读 SSE 增量）、`_find_json_objects()`（大括号配平扫描，跳过字符串内括号）、`extract_plan()`、`stream_chat()`（产出 phase / delta / done / error 四类事件） |
| `backend/main.py` | 新增 `POST /api/agent/chat/stream`（`StreamingResponse` + `text/event-stream`）。**旧 `POST /api/agent/chat` 原样保留**，冒烟测试与旧前端不受影响 |
| `frontend/src/api/filepilot.js` | 新增 `agentChatStream(message, context, handlers)`，返回「停止」函数。用 **fetch + ReadableStream** 而不是 EventSource——EventSource 只能发 GET，装不下 message/context |

**关键设计**：
- 本地规则命中时**零 token 也能流式**（服务端把说明逐块吐出，3 字/帧 + 15ms），让「零 token」与「有反应」不矛盾。

- 前端对旧后端有降级提示：流式接口 404 时提示「后端不支持流式对话，请重启本地服务」。

### v19-g：输入框「框里还有一个框」

用户看出输入框怪。**根因**：`global.css` 里 Element Plus 的输入聚焦样式是**带 `!important`** 的——
`.el-input__wrapper.is-focus, .el-textarea__inner:focus { border-color: var(--primary); box-shadow: var(--sh-focus) !important }`。
组件里那条 `box-shadow: none`（普通权重）根本压不住，所以聚焦时内层 textarea 会亮起
**主色边框 + 3.5px 聚焦环**，视觉上就是「胶囊里又套了一个输入框」。

**改法**：同样用 `!important` 反压（这是被迫的，不是偷懒）：

```css
.composer :deep(.el-textarea__inner),
.composer :deep(.el-textarea__inner:hover),
.composer :deep(.el-textarea__inner:focus) {
  background: transparent !important;
  border-color: transparent !important;
  box-shadow: none !important;
}
```

> **可复用规则**：凡是把 `el-input` / `el-textarea` 当作「自定义输入面的一部分」来用时
> （不做独立控件、不想要它自己的边框与聚焦环），**必须用 `!important` 覆盖**，
> 因为 global.css 的聚焦样式本身带 `!important`。

### v19-g 顺带：移动端输入框被裁掉底部

排查时发现：`@media (max-width: 960px)` 里 `.agent-shell { height: calc(100vh - 48px) }` 是错的——
移动端有一条**高度随内容换行变化**的顶栏，固定的 calc 减不干净，输入框底部会被裁。

改成不依赖顶栏高度的做法：

| 项 | 改法 |
|---|---|
| `.agent-shell` | `height: auto`（页面自然滚动） |
| `.agent-hero` | `min-height: calc(100vh - 320px)`（空态仍有高度可居中） |
| `.chat-scroll` | `flex: none; overflow-y: visible`（不再内部滚动） |
| `.composer-zone` | `position: sticky; bottom: 0` + `background: var(--bg)`（贴底且挡住滚动内容） |
| `.jump-bottom` | 改 `position: fixed; bottom: 148px` |

### v19-h：聚焦态不做任何视觉变化

v19-g 去掉内层框之后，胶囊自身聚焦时还剩「主色描边 + 蓝色光晕」；随后改成中性加深边框——**两种都没留下**。

用户要求：「选中边框不要加这种蓝色特效」，且加深也不要。

最终形态：**`.composer` 没有 `:focus-within` 规则**。
聚焦时边框、阴影、背景全部不变，连 `transition` 都不需要（没有属性在变）。
「已聚焦」这件事由**光标**承担，不靠边框表达。

> 这是本项目「装饰只用主色一个色相、且只在它表达状态时出现」的延伸：
> 输入框聚焦不是**状态**（不影响任何数据），只是**位置**，所以不值得染色。

### v19-i：空态示例 6 → 4 条

用户截图指出示例胶囊「少一点太占地方了，不协调」。

**根因**：6 句在 760px 宽里排不下（合计约 920px），断成「5 + 1」——最后一句孤零零占第二行，
既吃掉两行高度，又和上面一行失衡。

**改法**：**只留 4 句，正好排满一行**（约 540px，留有余量）：

```
扫描 D 盘 · D 盘空间都被谁占了 · 查找 D 盘重复文件 · 清理 C 盘垃圾
```

删掉的两句及理由：

| 删掉 | 理由 |
|---|---|
| `把 D:/大文件 搬到 E:/归档` | 最长的一句（17 字，约 250px），是断行的主因；迁移在侧栏「跨盘迁移」里能进 |
| `看看 D 盘有什么` | 与「扫描 D 盘」语义重复 |

> **可复用规则**：示例胶囊**按「一行排满」定数量**，不要按能力清单来凑。
> 判断方法：把候选句按 `字数 × 13 + 28` 估宽，加 8px 间距，超过 760px 就会断行；
> 断行后**只剩一个孤立的胶囊**是最难看的情况（宁可减到一行排得下的数量）。
> 新增示例前先跑一遍这个估算，别写完再看截图。

### v19-j：模型与 API Key 的可视化配置

**背景**：项目没有可视化后端，DeepSeek 的 key 原先只能靠环境变量，改一次要编辑文件 + 重启。

**为什么不为它开一个选项卡**（用户的疑问）：这个 key 只服务 Agent 页。离开 Agent 页，没人会想到去「设置」里找它；
而新开一级导航要动侧栏 / 路由 / 日志类型标签（落地清单九处），成本远高于 2 个字段。
判断标准：**设置项 > 5 个或涉及多个页面才值得开页，否则就地放在使用它的页面里。**

**落地形态（用户二选一后定为「模型名切模型、key 单独入口」）**：

| 入口 | 位置 | 弹层内容 |
|---|---|---|
| **齿轮** | 输入框右下，模型名左边 | API Key：当前状态（掩码 / 来自环境变量 / 未配置）+ 密码输入 + 保存 + 清除（仅当 key 存在设置文件里）+ 一行说明「保存在本机 .filepilot/settings.json，不会提交到仓库」 |
| **模型名** | 输入框右下 | 模型列表（当前项主色高亮 + 对勾）+ 自定义模型名输入框（回车应用）。**点一下即保存，不给多余的确认步骤** |

「+」菜单回归只放 配方 / 盘符 —— 配置类的东西不混进日常操作清单。

**后端**：

| 文件 | 改动 |
|---|---|
| `config.py` | 新增 `SETTINGS_FILE = STATE_DIR / "settings.json"` |
| `store.py` | 新增 `read_settings / save_settings / read_agent_settings / save_agent_settings`（复用既有 `load_json/save_json` + 锁） |
| `agent.py` | 新增 `resolve_key()`（**设置文件 → 环境变量**）、`resolve_model()`、`settings_view()`、`update_settings()`；原先把 `os.getenv("DEEPSEEK_API_KEY")` 的 6 处调用全改为这两个解析函数；两处请求体的 `model` 也改为动态解析 |
| `main.py` | `GET /api/settings/agent`、`POST /api/settings/agent`（`api_key` / `model` 传空串 = 清除该字段） |

**三条硬约束**：
1. **接口只回掩码**（`sk-te…cdef`），永不回传完整 key；前端也不预填 key（留空 = 不改动）。
2. **改完不用重启**——设置文件每次读取，改完立刻生效（这正是设置文件相对环境变量的最大好处）。
3. **清除 key 只动 `settings.json`**：配方（`recipes.json`）与所有任务记录不受影响（已实测 mtime 验证）。

> 已知取舍：key 以**明文**存在本机 `.filepilot/settings.json`（该目录已在 `.gitignore` 中）。
> 个人自用可接受；**若要对外分发，应换成系统凭据管理器 / DPAPI**。

**实测**：初始 `configured=false` → 保存假 key 后立刻 `configured=true`、`masked=sk-te…cdef`、`model=deepseek-reasoner`，
且完整 key **不出现在任何响应里**；清除后回到 `configured=false`；冒烟测试 73/73 全绿。

## v19-k：输入框对齐参考图 + 权限档位（2026-10-03）

用户给了两张图：参考图（目标）与我们的输入框。逐处对齐，并新增权限档位。

### 一、纯视觉对齐（三处）

| 处 | 改法 |
|---|---|
| `+` | 去掉 1px 圆形描边与 `border-radius`，纯加号（16 → 18px，hover 变 `--ink`） |
| 发送键 | `Promotion`（纸飞机）→ **`ArrowUpBold`**（↑）；禁用态从 `--inset` 淡底 → **`--ink-4` 中灰实心 + `--surface` 白箭头** |
| 「Enter 发送」 | 删除（参考图没有；`.composer__hint` 样式一并摘掉） |

### 二、API Key 入口换位置

参考图没有齿轮。齿轮（API Key）**并进「模型」弹层**：点右下角模型名 → 上半是模型列表、下半是 API Key（掩码 + 密码框 + 保存/清除），中间用 `.panel__divider` 分开。
输入框这一行只剩 `模型名 + 发送`，与参考图一致；key 的作用范围仍是 Agent 页，**不新开设置页**。

### 三、权限档位（本轮唯一的后端语义改动）

参考图左侧那个「⚠ 完全访问」是**权限模式开关**。本项目原先的硬约束是「桌面、`.workbuddy`、项目自身目录任何情况下不可改动」——
用户明确选择「真做权限模式开关」，因此**桌面被改为「软保护」**（可由完全访问档放开），其余两项仍是硬约束。

**三档**（`config.PERMISSION_MODES`，默认 `standard`）：

| 档 | 允许写 | 拦住 |
|---|---|---|
| `readonly` | 不写任何文件；扫描 / 预览 / 生成计划照常 | 写任务**在入口就被拒**（`main._launch`），不必等跑到一半才失败 |
| `standard` | 用户选的普通目录 | 软保护（桌面）+ 系统只读区 + 自保护 |
| `full` | 加上桌面与系统只读区 | 自保护目录；删除仍先进隔离区 |

**三条与档位无关的底限**（写进 `permissions.describe().guards`，前端弹层里也照实显示）：
1. 删除一律先进隔离区，永不直接删；
2. **自保护目录任何档位都不可写**——`.workbuddy`（运行数据）、项目自身、`.filepilot`（状态）、隔离区；
3. 切到 `full` 必须 `confirm=true`（前端弹一次确认框，**后端也拦**，缺 confirm 返回 400）。

**落地**：
- `backend/permissions.py`（新，唯一档位解析处；不 import fsutil，避免与 fsutil 循环依赖）
- `config.py`：`SOFT_PROTECTED_DIRS` / `SELF_PROTECTED_DIRS` / `SAFETY_BLOCKLIST`（= 软 + 自，读取剪枝用）/ `PERMISSION_MODES` / `WRITE_JOB_TYPES`
- `fsutil.py`：新增 `write_block_reason(path, mode)` 与 `assert_writable(path, mode)`——**档位作为参数传入**，fsutil 保持纯原语、不读设置
- `clean` / `migrate` / `junk` / `backup`：按档位把门（每个任务只读一次设置）；`junk` 与 `migrate` 的跳过判定改用 `write_block_reason`
- `jobs.py`：每个任务在 `_blank_job` 记录 `permission`，成功/取消/失败日志一并带上，事后可查「这次是谁放的权限」
- `main.py`：`GET/POST /api/settings/safety`；`/api/config` 的 `safety` 段补 `self_protected` 与 `permission`
- 前端：输入框 `+` 后面是档位胶囊（`standard` 灰锁 / `readonly` 灰眼 / `full` **橙底警告**），点开切档

> **例外**：`migrate` 的 `dry_run`（只生成计划，清单 CSV 写在 `.filepilot/reports`）在 `readonly` 档**放行**——
> 它不动用户文件。若不做这个例外，只读档连"规划一次迁移"都做不了。

**验证**：新增 `tests/permission_test.py`（19 项，含门禁判定矩阵，**不碰任何真实文件**）全绿；
主冒烟测试结果与改动前一致（72/73，唯一失败项是后端新本地规则接住了「今天天气怎么样」，与本轮无关）。
