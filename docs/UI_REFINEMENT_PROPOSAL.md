# Atlas 界面精修设计方案（v19 提案）

> 性质：**纯设计方案，不含代码实现**。
> 前提：完全延续 `UI_REVAMP.md` v11~v17 定稿的形态（灰底 + 纯白卡、单色相蓝、贴边侧栏、无桌面顶栏），只做精修与信息增量，不推翻任何已定结论。
> 目标关键词：**大气、干净**。手段：尺度放大、节奏对齐、信息分层，**不靠增加颜色与装饰**。

---

## 一、布局调整

### 1.1 内容区网格基线

当前各页 padding 与卡片内距由历史版本叠加而来，建议统一为一套 8pt 网格：

| 层级 | 现状（约） | 提案 |
|---|---|---|
| 页面左右内边距 | 各页不一 | **32px**（<1280px 窗口降为 24px） |
| 页面上边距 | 22px | **28px**（无顶栏后，H1 需要更从容的起始呼吸位） |
| `section-stack` 段间距 | 20px | **24px** |
| 卡片内边距 | 各组件不一 | **统一 24px**（表格卡上下 16px / 左右 0，由单元格自承内距） |
| 卡片圆角 | `--radius` 20px | 不变，**全站唯一卡片圆角**，不再出现 10/12/26 混用 |

### 1.2 首页（总览）重排

首页是「大气」的第一印象面，建议改为**三段式纵向节奏**：

```
┌────────────────────────────────────────────┐
│ PageHeader（eyebrow + H1 + meta-pills）     │
├────────────────────────────────────────────┤
│ ① 关键指标带：3 张 StatCard 横排（不变）      │
│ ② 磁盘明细表 + 接口调用 TOP（左右 7:5）  ★新  │
│ ③ 最近任务表（整行通宽）                  ★新  │
├────────────────────────────────────────────┤
│ 快捷入口 4 张 ActionTile（收尾，不变）        │
└────────────────────────────────────────────┘
```

- **② 左右分栏比例 7:5**，两卡顶对齐、同高（由内容较高者撑开）。
- **③ 最近任务**目前是 6 条简单列表，升级为正式 `DataTable`（见 §4.3），通宽放置。
- 快捷入口移到最底：它是「去向」而非「状态」，放在信息之后符合阅读动线。

### 1.3 分析类页面的「筛选行」归位

`扫描分析 / 操作日志 / 任务中心` 三页各自有筛选控件，位置与密度不一致。提案：

- 筛选行统一为**卡片外的独立一行**（不放卡内），左对齐排布，行高 40px；
- 顺序约定：**主筛选 → 次筛选 → 弹性空隙 → 右侧操作（刷新 / 导出）**；
- 筛选控件一律 `default` 尺寸，不混用 `small`；标签不写「筛选：」前缀，控件占位文本即含义。

### 1.4 明细页的双栏规则

`任务中心` 这类「列表 + 详情」页：

- 列表 : 详情 = **5:7**（详情是主角，列表是索引）；
- 两栏**同高、顶对齐**，详情卡内部用 `--hairline` 分段而非再套子卡片；
- <1100px 窗口时上下堆叠，列表在上。

## 二、视觉规范精修

> 以下均是对 `global.css` 既有令牌的**用法收敛**，不新增色相、不新增装饰。

### 2.1 数字排版（本轮最重要的精修点）

「大气」在数据类产品里 80% 来自数字的呈现：

| 规则 | 说明 |
|---|---|
| **等宽数字** | 所有数值（StatCard 数值、表格内数字、磁盘百分比）加 `font-variant-numeric: tabular-nums`，杜绝进位抖动与对不齐 |
| **数值分级** | StatCard 主数值 42px（已定）保持；表格内数字 13.5px / 600；单位降一级（12px / `--ink-3`），**不与数字同字重** |
| **千分位** | 文件数、字节数一律千分位分隔；容量单位最多保留 1 位小数 |
| **对齐** | 表格中数字列**右对齐**，表头同步右对齐；文本列左对齐；状态列居中 |

### 2.2 层级纪律（三条复述 + 一条新增）

延续已定原则，再补一条：

1. 层次只来自「卡片比页面底白」这一条明度差（v11 定稿，不动）；
2. 发丝线承担分隔，投影只保留 `--sh-1` 静置 / `--sh-2` 悬停两档；
3. 装饰只用主色一个色相，语义色只在表达状态时出现（v6 定稿，不动）；
4. **新增：同屏最多 3 个视觉重心**。重心 = 大数字、主色填充按钮、语义色标签。超出时降级的优先级：先降按钮（主色→默认），再降标签（彩色→中性），大数字不动。

### 2.3 文字层级收敛

| 角色 | 令牌 | 用途边界 |
|---|---|---|
| `--ink` | 正文、标题、数值 | 承载主要信息 |
| `--ink-2` | 次要信息、表头 | 表格表头从 `--ink-3` 提到 `--ink-2`（表头被扫视频率高） |
| `--ink-3` | 辅助说明、单位、时间戳 | 最低信息级文字 |
| `--ink-4` | **仅装饰**（分隔符 ·、占位符 —） | 已有铁律，重申 |

### 2.4 状态标签统一

全站状态目前散在 `el-tag` 的 type 上。提案收敛为一种形态：

- **点 + 文字**（6px 状态圆点 + 13px 文字），无底色填充、无描边；
- 圆点色 = 语义色，文字色 = `--ink-2`；
- 位置固定为表格最后一列之前或行尾；
- 例外：`等待确认` 这类**需要行动**的状态，升级为 `--warning-soft` 底 + `--warning-ink` 字的药丸，在一屏中允许它是唯一的彩色填充元素。

### 2.5 图标与留白

- 图标尺寸全站只留三档：**20px（侧栏）/ 18px（卡内标题）/ 16px（按钮与行内）**；
- 卡片标题行与正文之间 16px；正文块之间 12px；**不允许用空行 div 撑间距**；
- 表格行高：默认 48px，提供「紧凑 40px」密度切换（仅长列表页显示该开关）。

## 三、组件优化建议

| 组件 | 现状问题 | 优化提案 |
|---|---|---|
| **StatCard** | 只有静态数值 + 一句 note | ① note 行升级为「**次级指标**」（如「较上次扫描 +12%」或「等待确认 3 个」），用 `--ink-2`，不染色；② 数值刷新沿用 `num-pop`，不新增动效；③ 卡内不加图表，保持纯粹 |
| **DataTable** | 各页表头/对齐/空态不统一 | ① 表头 12px / 600 / `--ink-2` / 大写字距 0.02em；② 数字列右对齐（见 §2.1）；③ 空态统一 `EmptyState`（已有）；④ 行 hover 只改 `--surface-2`，不出边框；⑤ **保留可见滚动条**（v14 已明确长列表不隐藏） |
| **进度条（磁盘）** | 已较好 | 仅补：百分比数字与进度条右端对齐，刻度数（75%/90%）用 `--ink-4` 装饰级 |
| **ActionTile** | 已较好 | hover 箭头张开保留；图标色块从实心主色降为 `--primary-soft` 底 + 主色图标（与侧栏选中态同构，全站「主色出现方式」收敛为这一种） |
| **meta-pill** | 首页两枚文案偏口号 | 文案改为纯术语：「本机运行」「零 Token（Agent 除外）」；数量控制在 ≤2 枚 |
| **EmptyState** | 已统一 | 不动 |
| **JobProgress** | 已较好 | 仅统一：进度百分比与状态词之间用 `·` 分隔符（`--ink-4`），不新增颜色 |

## 四、新增数据表设计思路

> 原则：**全部数据来自本地已有接口或本地文件状态，零 token、零新增网络依赖**。
> 每张表都给出：位置 / 数据列 / 交互 / 空态。列顺序即重要度顺序。

### 4.1 磁盘健康明细表 ★（首页 ②左）

| 项 | 设计 |
|---|---|
| 数据列 | 盘符 · 文件系统 · 已用 · 可用 · 总计 · 占用率（内嵌细进度条 + 数值）· 状态 |
| 状态列 | 三级：正常（无标签，只有 `--primary` 进度条）/ 偏高 ≥75%（warning 点）/ 告急 ≥90%（danger 点）——**沿用磁盘条既有阈值与色级，不新造规则** |
| 交互 | 点击行 → 跳「空间地图」并定位该盘；行 hover 提亮 |
| 空态 | 「后端服务未就绪」（沿用现有） |

设计理由：现有磁盘条信息散在卡片里，**表格化后「盘符—占用—状态」一行的扫视成本最低**，且为后续多盘扩展留了行空间。

### 4.2 接口调用统计表（首页 ②右，扩展现有 TOP 5）

| 项 | 设计 |
|---|---|
| 数据列 | 接口 · 调用次数 · 占比（细条）· 最近调用时间 |
| 行数 | 固定 TOP 8，底部一行「查看全部 →」跳「操作日志」预过滤 |
| 交互 | 只读，无排序（首页不做重交互） |
| 空态 | 「暂无调用记录」 |

### 4.3 最近任务表 ★（首页 ③通宽）

| 项 | 设计 |
|---|---|
| 数据列 | 任务类型 · 目标路径（截断 + tooltip）· 结果摘要（名词短语，如「释放 2.4 GB · 38 项」）· 耗时 · 完成时间 · 状态 |
| 行数 | 最近 6 条，右上角「全部任务 →」 |
| 交互 | 点击行 → 跳「任务中心」并选中该任务；`失败` 状态行尾追加「回滚」文字按钮（danger 文字色，无底色） |
| 空态 | 「暂无任务记录」 |

设计理由：把首页从「指标陈列」升级为「**状态 + 流水**」的仪表盘，是本轮信息增量的核心。结果摘要用名词短语，符合 v8「删句子留名词」。

### 4.4 大文件 TOP 10 表（扫描分析页，结果区追加）

| 项 | 设计 |
|---|---|
| 数据列 | 排名 · 文件名 · 所在目录（`--ink-3`）· 大小 · 类型 · 修改时间 |
| 交互 | 列头可排序（大小 / 时间）；点击行 → 系统「打开所在位置」（本地能力）；不提供删除入口——删除动作只走「垃圾扫描 / 查重」的确认流 |
| 空态 | 扫描未运行时显示「先运行一次扫描」+「去扫描」按钮（复用 `EmptyState` 带操作） |

### 4.5 文件类型分布表（扫描分析页 / 空间地图页侧栏）

| 项 | 设计 |
|---|---|
| 数据列 | 类型（图标 + 扩展名）· 文件数 · 总大小 · 占比（细条） |
| 行数 | TOP 10 + 「其他」合并行 |
| 交互 | 点击类型 → 空间地图按类型高亮过滤 |
| 备注 | 类型分类规则只能来自 `backend/config.py`（架构铁律），前端不写死 |

### 4.6 回收站构成表（回收站页顶部追加）

| 项 | 设计 |
|---|---|
| 数据列 | 来源操作（垃圾清理 / 查重 / 迁移 / 手动）· 项目数 · 占用空间 · 最早进入时间 |
| 交互 | 点击行 → 下方明细列表按来源过滤；行尾「还原该类」「清空该类」文字按钮 |
| 空态 | 「隔离区为空」 |

设计理由：回收站目前是一坨平铺列表，**按来源聚合**后「这批东西能不能删」的判断成本最低，与「一切删除先出清单」的安全文化一致。

### 4.7 查重分组汇总表（重复文件页结果区）

| 项 | 设计 |
|---|---|
| 数据列 | 组号 · 文件数 · 单文件大小 · 冗余占用 · 哈希前缀（8 位）· 分布目录数 |
| 交互 | 点击组 → 展开组内文件明细（行内展开，不跳页）；表头按「冗余占用」默认降序 |
| 空态 | 「未发现重复文件」 |

### 新增表的统一约束（写进规范）

1. **零 token**：数据全部来自本地接口 / `.filepilot/` 状态文件；
2. **无新色相**：表内彩色只允许出现在状态点与进度条（既有三级色级）；
3. **滚动条可见**：所有表格页保留 11px 系统条（v14 的隐藏仅限侧栏导航）；
4. **密度切换**：仅 `任务中心 / 操作日志 / 大文件表` 提供 40px 紧凑档；
5. **空态三件套**：图标 + 名词标题 + 至多一个操作按钮，不写说明句；
6. **导出入口**：仅 `操作日志 / 任务中心` 保留，放筛选行最右（§1.3）。

## 五、不做清单（防止翻烙饼）

以下与已定稿结论冲突，本方案**明确不做**：

1. 不恢复桌面顶栏、不恢复侧栏状态行、不恢复分组标题；
2. 不给卡片加 `backdrop-filter`、不加背景纹理 / 光晕 / 彩色装饰线；
3. 不引入图表库（环形图 / 折线图需要新依赖与接口，超出「精修」范围；占比一律用细进度条表达）；
4. 不压侧栏行高、不改单行 52px 导航形态；
5. 不新增主题色、不动 `--bg #F4F5F7` / `--surface #FFFFFF` 的明度分层；
6. 不给首页加「欢迎语 / 问候语 / 日期横幅」——v8 已删干净，不回潮。
